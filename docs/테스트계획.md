## 0. 원칙

- 테스트 ID: `T-<요구 ID>-<번호>`. 요구 ID의 점은 뺀다(F-01.3 → `T-F013-01`). 보안 전용은 `T-CSP-`, `T-NAV-`, `T-AST-`, `T-SEC-`.
- 완료 기준 한 줄마다 테스트를 최소 1개 둔다. 기준에 없는 경계·실패 경우는 "(추가)"로 표시한다.
- 판정은 릴리스 빌드(`npm run tauri build`의 설치본 또는 `src-tauri/target/release/wy-note.exe`)로 한다. 개발 실행(`tauri dev`)은 CSP·devUrl·디버그 빌드 속도가 달라 성능·보안 판정에 쓰지 않는다.
- 결함은 테스트 ID·재현 절차·기대·실제·증거 경로로 NOTE-pm에 `[결함]` 보고한다.
- 증거(화면 캡처·로그·측정 CSV)는 저장소 밖 `%USERPROFILE%\wy-note-qa\evidence\<날짜>\<테스트 ID>\`에 둔다. API 키·노트 실데이터가 찍힌 증거는 남기지 않는다.

## 1. 테스트 환경과 방법

### 1.1 방법 구분

| 표기 | 뜻 | 도구 |
|---|---|---|
| 수동 | 사람이 앱 화면을 조작하고 눈으로 판정 | 릴리스 빌드 앱, 화면 캡처 |
| 자동 | 실행 중인 앱의 WebView2에 원격 디버깅(CDP)으로 붙어 조작·관찰 | 앱 실행 전 환경 변수 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`. QA 세션 전용 브라우저 자동화 도구로 `http://127.0.0.1:9333`에 붙는다. 순수 브라우저(vite만)에서는 `invoke`가 없으므로 쓰지 않는다 |
| Rust | `src-tauri`의 `cargo test`(메모리 DB 또는 임시 파일 DB) | 계약-DB 10절의 단위 테스트 + 이 문서가 요청하는 항목 |
| 측정 | 시간·메모리·네트워크를 재서 수치로 판정 | PowerShell, 화면 녹화(Xbox Game Bar `Win+Alt+R`, 60fps 설정), CDP Performance, Python `sqlite3`(읽기 전용) |
| 코드 | 소스·설정 검색으로 확인 | Grep, `git log -p -S` |

- 원격 디버깅 포트는 성능 측정(시작 시간·메모리)에는 켜지 않는다. 포트가 켜진 상태의 수치는 참고로만 적는다.
- DB 확인은 Python `sqlite3`로 `file:<경로>?mode=ro` URI를 열어 읽기만 한다(앱 실행 중에도 WAL이라 안전). 쓰기는 테스트 데이터 준비 때 앱을 끈 상태에서만 한다.

### 1.2 데이터 폴더 격리

- 데이터 폴더는 식별자로 고정이다(`%APPDATA%\com.wynote.desktop`, D-14). 테스트 전 앱을 끄고 기존 폴더를 `com.wynote.desktop.qa-backup-<시각>`으로 이름을 바꿔 두고, 끝나면 테스트 폴더를 지우고 이름을 되돌린다. WebView2 사용자 데이터(`%LOCALAPPDATA%\com.wynote.desktop`)도 같은 방식으로 다룬다. (→ 확인 11)
- 테스트 API 키는 저장소 밖에만 둔다. 실제 Claude API 호출이 들어가는 테스트(1.4절 표의 "외부 호출" 표시)는 실행할 때마다 NOTE-pm 승인을 받는다.

| D5 | 이미지 파일: png·jpg·jpeg·gif(움직임)·webp·svg(정상), `<script>`가 든 svg, 확장자만 png인 텍스트 파일, bmp, 0바이트 png, 20MB png | 저장소 밖 `tools\images\`에 준비 |

D2 생성 규칙
- 난수는 시드 고정 LCG(`x = (1103515245x + 12345) mod 2^31`, 시드 20261026)로 만들어 같은 데이터를 다시 만들 수 있게 한다.
- 트리: 최상위 20개, 단계마다 자식 0~8개, 최대 깊이 5. 정확히 1,000개가 되면 멈춘다.
- 크기: D3 1개(5만 자) + 나머지 999개는 평균 약 9,960자(2,000~20,000자 균등 분포에서 뽑고, 합계가 10,000,000 ± 1%가 되게 마지막에 맞춤).
- 글: 한글 낱말 약 2,000개 목록(저장소 밖 파일) 80% + 영어 낱말 15% + 숫자 5%. 문단 200~600자, 문단 10개마다 제목 블록, 페이지마다 목록·체크리스트·코드·표 중 1~2개.
- 찾을 낱말 심기(정답 개수를 알기 위해): `회의록`은 정확히 37개 페이지에, `의록에`(어절 중간)는 5개 페이지에, 고유 표식 `QAZ0001`~`QAZ1000`은 페이지마다 하나씩(페이지 끝 문단), 2글자 `결재`는 300개 페이지에, 한 글자 `뷁`은 3개 페이지에. `없는검색어`는 어디에도 넣지 않는다(전체 훑기 최악 경우).
- 만든 뒤 확인: `select count(*) from pages` = 1000, `select sum(length(body)) from page_fts` ≈ 1,000만, `QAZ0500` 검색 1건.

메모리 합계 스크립트(PowerShell, 앱 프로세스와 그 자손 전체)
```powershell
$all = Get-CimInstance Win32_Process
$root = $all | Where-Object { $_.Name -eq 'wy-note.exe' }
$ids = @($root.ProcessId); $i = 0
while ($i -lt $ids.Count) { $ids += ($all | Where-Object { $_.ParentProcessId -eq $ids[$i] }).ProcessId; $i++ }
$procs = Get-Process -Id $ids -ErrorAction SilentlyContinue
"{0} procs, Private {1:N1} MB, WorkingSet {2:N1} MB" -f $procs.Count, (($procs | Measure-Object PrivateMemorySize64 -Sum).Sum/1MB), (($procs | Measure-Object WorkingSet64 -Sum).Sum/1MB)
```

## 14. 기획 확인 필요

기능정의를 고치지 않고 모아 둔다. 각 항목은 영향받는 테스트를 적었다.

**저장·성능 기준**
1. **강제 종료 기준과 저장 간격이 부딪힘**: F-05 "강제 종료 1초 전까지 입력한 내용이 남아 있다"와 NF-02 "계속 입력 중이면 5초마다"가 맞지 않는다. 계속 입력하다 강제 종료하면 최대 5초 분량을 잃을 수 있고, 입력을 멈춘 경우에도 1초 디바운스 + 저장 시간 때문에 "정확히 1초 전"은 경계에 걸린다. 제안: "입력을 멈춘 뒤 '저장됨'이 보이면 강제 종료해도 남는다. 계속 입력 중에는 최대 5초 분량까지 잃을 수 있다." (T-F05-05·06)
2. **성능 측정의 시작·끝 지점과 판정 규칙이 없음**: 시작 3초의 "편집 가능" 정의, 차가운 시작(재부팅 직후)도 판정하는지, 페이지 전환 1초의 끝 지점(본문 전체 표시인지 첫 화면인지), 검색 0.5초에 화면 입력 대기(화면설계 초안 120ms)를 넣는지, 반복 측정의 판정값(최댓값·p95). 이 문서는 최댓값으로 가정했다. (T-NF04-01~04)
3. **입력 지연 기준에 수치가 없음**: NF-04 "타이핑이 끊기지 않는다". 제안: 키 입력~화면 반영 p95 50ms 이하, 최대 100ms 이하. 한글 입력기 조합 중 끊김은 수동 판정. (T-NF04-05)
4. **메모리 측정 조건**: 유휴 300MB를 빈 DB에서 재는지 D2(1,000페이지)에서 재는지, AI 패널 열림 여부. F-03의 페이지별 실행 취소 기록(에디터 상태를 페이지마다 보관)이 오래 쓰면 메모리를 키운다. 보관 개수·크기 상한이 필요한지. (T-NF04-06·07)

**보안·저장 위치**
5. **CSP·탐색 차단·링크 동작 기준이 없음**: 기능정의·결정기록에 CSP가 없고 지금 `csp: null`이다. 노트 안 링크를 누를 때의 동작(무시 / Ctrl+클릭으로 기본 브라우저)도 정해지지 않았다(화면설계 초안에는 링크 모양만 있음). `opener:default`는 Tauri 기본값상 http·https 주소를 기본 브라우저로 여는 권한을 포함하는 것으로 알고 있어, D-18 "그 밖의 URL 열기 권한은 더하지 않는다"의 의도(외부 열기 금지?)와 맞는지 확인 필요(T-SEC-04로 실제 확인 예정). 새로 고침(F5)·확대·기본 오른쪽 클릭 메뉴를 막을지도. (T-CSP-*, T-NAV-*, T-SEC-04)
6. **AI 호출을 어디서 하는지 미정**: WebView에서 직접 호출하면 키가 WebView로 넘어오고(NF-05 "키는 한 모듈에만"과 충돌 소지) CSP `connect-src`에 `api.anthropic.com`을 열어야 한다. Rust에서 호출하면 둘 다 필요 없다. AI·키·설정용 Tauri 명령은 계약-DB v1에 없다. (T-NF05-04, T-CSP-01)
7. **계약 v1에 없는 저장 항목**: AI 전송 제외, 하루 상한·사용 횟수, 사용 기록, 테마, 사이드바 너비·접힘, AI 패널 열림, 최근 연 페이지(화면설계 초안), 마크다운 내보내기(데이터 폴더 밖에 쓰기, 저장 창 — dialog·fs 권한 필요 여부). D-06은 "설정·AI 사용 기록도 SQLite"인데 명령·테이블이 없다. 화면이 `localStorage`에 두면 WebView2 데이터(`%LOCALAPPDATA%`)로 가서 NF-01 "한 폴더 복사 = 백업"이 깨진다. (T-NF01-03·05, T-F085-*)
8. **NF-05 "키는 API 호출 때만 읽는다"와 F-08.6 끝 4자리 표시·"API 키 없음" 판단이 부딪힘**: 키가 있는지 알고 끝 4자리를 보이려면 호출 밖에서도 읽어야 한다. 허용 범위(존재 확인 / 끝 4자리 따로 보관)를 정해야 한다. 오프라인에서 "확인" 없이 저장할 수 있는지도(F-08.6 "저장·삭제는 된다" vs 화면설계 "확인되면 저장 활성"). (T-NF05-05, T-F086-03)
9. **외부 HTML 붙여넣기 속 원격 이미지**: `<img src="https://…">`를 붙여넣으면 그대로 두면 네트워크 요청(NF-06 위반)이고 계약(이미지 `src` = 파일 이름만)과도 어긋난다. 내려받아 첨부로 / 버림 / 링크로 남김 중 정해야 한다. `data:` 이미지도 첨부로 바꾸는지. (T-NAV-05)
10. **SVG 허용**: 계약은 svg를 허용 확장자에 넣었다. SVG에는 스크립트가 들어갈 수 있다. `<img>`로만 보이면 실행되지 않지만 주소로 직접 열리면 실행될 수 있다. svg를 빼거나, wyasset 응답에 `Content-Security-Policy: script-src 'none'`을 붙이는 등 정책 필요. (T-AST-07)
11. **테스트 데이터 격리**: 식별자가 고정이라(D-14) 테스트가 사용자의 실제 데이터 폴더를 쓴다. 이 문서는 "앱 종료 → 폴더 이름 바꿔 보관 → 끝나면 되돌림"으로 가정했다. 사용자가 이미 앱을 쓰기 시작했다면 그 절차를 허락받아야 하고, 아니면 디버그 빌드 전용 데이터 폴더 바꾸기(코드 변경)가 필요하다. D2 생성 스크립트는 QA가 저장소 밖에 두고 CDP로 invoke를 부르는 방식으로 가정했다. (1.2·1.3절)
12. **AI 실패 경우를 만들 수단**: 시간 초과·크레딧 소진·응답 지연은 실제 API로 만들 수 없다. 디버그 빌드에서 API 주소를 바꿀 수 있게 하는 시험용 길(코드 변경)이 필요한지, Rust 단위의 오류 분류만으로 갈지. 실제 호출 테스트의 크레딧 사용 허락 범위도. (T-F08-03·05, T-F082-03)
13. **WebView2 런타임 자체 통신**: WebView2가 SmartScreen·구성 요소 갱신 등으로 Microsoft에 연결할 수 있다. NF-06 "앱은 네트워크 요청을 하지 않는다"에 이것도 드는지, 브라우저 인자로 끌지. (T-NF06-03)

**기능 동작**
14. **휴지통 복원 — 부모가 따로 휴지통에 있을 때**: 기능정의는 "부모가 영구 삭제되었으면 최상위"만 말한다. 계약은 "부모가 아직 휴지통이면 최상위 맨 끝". 이것으로 확정인지, 휴지통 목록 경로 문구는 어떻게 보일지. (T-F013-06)
15. **페이지 삭제 직후 Ctrl+Z**: F-03은 "페이지 삭제의 되돌리기는 실행 취소가 아니라 복원"인데, 화면설계 초안의 알림에는 `[실행 취소]`(= 바로 복원) 버튼이 있다. 단축키 Ctrl+Z가 이 알림 버튼과 같은 일을 하는지, 아무 일도 안 하는지. (T-F03-08)
16. **저장 전 검색**: F-04 "방금 저장한 내용이 바로 나온다"는 저장 뒤 기준이다. 입력하고 1초 안에 Ctrl+K를 누르면 아직 저장 전이라 안 나온다. 검색을 열 때 저장 대기분을 먼저 저장할지. (T-F04-04)
17. **"첫 일치 위치로 스크롤"의 경계**: 제목에만 일치할 때, 일치가 서식(굵게 등) 경계를 걸칠 때, 1~2글자 LIKE 결과(Rust 평문 기준 위치)를 편집기 위치로 옮길 때의 기대 동작. (T-F04-02)
18. **입력 길이 상한이 바뀌는지와 세는 단위**: F-08.5 "상한(기본 2만 자)"의 "기본"은 바꿀 수 있다는 뜻으로 읽히는데 같은 절에는 호출 횟수만 "설정에서 바꿀 수 있다"고 하고 화면설계 초안은 고정이다. 글자 수를 무엇으로 세는지(UTF-16 단위 / 유니코드 문자 / 바이트). (T-F085-04, T-F083-07)
19. **하루 상한의 날짜 경계·집계 대상**: "하루"가 로컬 자정 기준인지, "남은 시간"이 자정까지인지. 실패한 호출·중지한 호출·키 "확인" 시험 호출을 횟수에 넣는지. (T-F085-01·03·10)
20. **AI 전송 제외의 하위 적용**: "하위 페이지에도 적용할지 고를 수 있다"에서, 나중에 그 아래 새로 만든 페이지와 옮겨 온 페이지, 밖으로 옮겨 나간 페이지는 어떻게 되는지. (T-F085-07)
21. **다듬기 결과 "바꾸기"의 대상 범위**: 요청 뒤 사용자가 선택을 바꾸거나 원문을 고쳤을 때 무엇을 바꾸는지(요청 때 범위 / 지금 선택 / 원문이 바뀌었으면 막기). (T-F082-03)
22. **오프라인 판정 방법**: 랜은 연결되었지만 인터넷이 안 되는 경우를 "오프라인"으로 볼지 "호출 실패"로 볼지, 연결 회복을 얼마 안에 알아채야 하는지. (T-F08-02)
23. **내보내기 대상 폴더에 같은 이름이 있을 때**: 덮어쓰기 / 새 이름 / 묻기. 하위 포함 때 이미지 폴더 이름 규칙. (T-F06-08)
24. **코드 블록의 Tab 가둠과 키보드만으로 나가기**: F-02.4 "Tab이 블록 밖으로 포커스를 빼지 않는다"면 키보드만 쓰는 사용자가 코드 블록에서 나가는 방법(예: 끝에서 ↓, Ctrl+Enter, Esc 후 Tab)이 정해져야 F-02 "키보드만으로"와 접근성(키보드 갇힘)을 판정할 수 있다. (T-F024-02)
25. **Alt+↑/↓의 이동 단위**: 목록 항목·중첩 목록·표 셀·코드 블록 안에 커서가 있을 때 옮기는 것이 항목인지 블록 전체인지. (T-F027-03)
26. **이미지 크기·형식 상한**: 파일 크기 상한이 없다(100MB 붙여넣기 때 IPC·메모리). 허용 형식(png·jpg·jpeg·gif·webp·svg) 밖(bmp·ico·heic)을 거부 또는 변환. (T-F026-05, T-SEC-03)
27. **화면설계에서 늘어난 상태 유지 항목**: 사이드바 너비·접힘, AI 패널 열림 유지, 테마는 기능정의에 없다. 화면설계가 확정되면 그것을 테스트 근거로 삼아도 되는지. (화면 칸 채울 때)
28. **저장 실패 뒤 다시 시도 시점**: 기능정의 "다음 저장 때 다시 시도", 계약 "다음 디바운스 때", 화면설계 초안 "5초마다 다시 저장". 입력이 더 없을 때도 저절로 다시 시도하는지. (T-F05-07)
