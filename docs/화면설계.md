## 설계 방향

- **매일 켜 두는 작업 도구.** 장식보다 읽기·찾기·고치기가 빠른 화면. 중립 회색 두 겹(종이색 편집 영역 + 한 단계 어두운 사이드바·AI 패널)에 강조색은 한 번에 하나만 쓴다. 기본은 먹청록이고, 설정에서 프리셋 5개(먹청록·남색·자주·주황 갈색·회색) 중 하나로 바꿀 수 있다(v0.5, P5-2). 강조색은 주 버튼, 지금 위치(열린 페이지·선택), 끌기 위치선에만 쓴다. 키보드 포커스는 따로 하늘색(`--color-focus-ring`, v0.5)으로 보여 선택·지금 위치와 헷갈리지 않게 한다.
- **밀도.** UI 글자 13~14px, 트리 행 28px, 버튼 30px. 본문만 16px·줄 간격 1.7로 넉넉하게 둔다(한글 가독성). 누르는 영역은 24px 이상(WCAG 2.2 AA 2.5.8, 사용자 결정 4-③) — 공통 규칙 "누르는 영역".
- **Windows 데스크탑에 익숙하게.** 창 틀은 Windows 기본 제목 표시줄을 쓴다(Tauri `decorations: true`). 글꼴은 시스템 글꼴(Segoe UI + 맑은 고딕, 앱에 글꼴 파일을 넣지 않음, 사용자 결정 4-①). 아이콘은 `lucide-react`(사용자 결정 4-①). 맥락 메뉴는 오른쪽 클릭과 `⋯` 버튼 둘 다로 연다.
- **AI는 덧붙임.** AI 패널을 닫아도 화면이 완결된다. AI 상태(키 없음·오프라인·상한)는 패널 안에서만 알리고 편집 영역을 막지 않는다(F-08 실패 격리).
- **모달은 되돌리기 어려운 일에만.** 삭제 확인(S-03), 내보내기(S-11), 저장 못 한 채 닫기(S-12)만 대화상자다. 휴지통·설정은 가운데 영역에 여는 화면이다. 검색(S-05)은 입력에 집중해야 해서 겹치는 창으로 둔다.
- **노트 밖으로 나가는 길을 만들지 않는다.** 붙여넣은 원격 이미지는 넣지 않고, 링크는 열지 않는다(사용자 결정 2-①·2-③). 대신 무엇을 하지 않았는지 알린다(S-13).

## S-01 앱 셸

```
┌ Windows 제목 표시줄 (wy-note) ──────────────────────────────────────────┐
│ 사이드바 248px     │ 위 막대 44px: 경로 · 저장 상태 · [AI] · [⋯]   │ AI 340px │
│ wy-note       [◧] │──────────────────────────────────────────────│ AI  12/50 ✕│
│ [검색   Ctrl K]   │                                              │ 요약|다듬기|질문│
│ + 새 페이지        │      페이지 제목 (34px)                      │          │
│ 페이지             │      본문 최대 720px, 왼쪽 72px 손잡이 자리     │ 대화     │
│  ▾ 업무            │                                              │          │
│    ▾ 회의록        │                                              │          │
│      ■ 10월 4주…   │                                              │ [입력창] │
│ ─────────────     │                                              │          │
│ 휴지통 3 / 설정    │                                              │          │
└───────────────────┴──────────────────────────────────────────────┴──────────┘
```

- 배치: CSS grid 3열(`--sidebar-width` / 나머지 / `--ai-panel-width`).
- 사이드바: 오른쪽 경계를 끌어 200~360px. `Ctrl+\`로 접기·펴기(접으면 0px, 위 막대 왼쪽에 펴기 버튼이 나온다). 너비·접힘 상태는 다시 시작해도 유지한다(F-07의 창 상태와 같이 저장).
- AI 패널: **접기 가능.** 위 막대의 `AI` 토글 버튼, 패널의 `✕`, `Ctrl+J`로 연다·닫는다. 닫으면 0px(얇은 띠도 남기지 않는다). 왼쪽 경계를 끌어 300~480px. 열림 상태는 다시 시작해도 유지한다. API 키가 없어도 패널은 열리고 안내를 보여 준다(S-07).
- 위 막대(편집 영역): 경로(조상 페이지 이름, 누르면 그 페이지로 이동) · 저장 상태 · `AI` 토글 · 페이지 메뉴 `⋯`.
  - 저장 상태(F-05): `● 저장됨`(초록 점) / `● 저장 중`(회색 점) / `● 저장 안 됨`(빨강, S-10). 글자 12px, 3단계 색.
  - 페이지 메뉴 `⋯`: 하위 페이지 추가 · 마크다운으로 내보내기(S-11) · AI 전송 제외(켜짐 표시) · 휴지통으로 이동. 트리 맥락 메뉴(S-02)와 같은 항목·같은 순서.
- 창 최소 크기 **900 × 600px(확정, 사용자 결정 4-②)**, 첫 실행 기본 크기 **1200 × 800px(D-30 ⑥)**. 그 뒤로는 마지막 창 크기·위치를 기억해 연다(F-07).
- **좁은 창(v0.4, pm 결정)**: AI 패널이 열려 있을 때만 적용한다. 기준은 창 너비가 아니라 **본문 너비 480px**이다.
  - 본문 너비 = 창 − 사이드바(펴면 248, 접으면 0) − AI 패널 340 − 편집 여백 2×`--editor-gutter` − 스크롤바·경계 약 10.
  - 여백: 창이 1100px 미만이면 `--editor-gutter`를 72 → 40px로 줄인다. 1100px 이상에서는 72px 그대로 둔다.
  - 겹치기: 본문이 480px 밑이면 AI 패널을 그리드 열에서 빼고 편집 영역 오른쪽 위에 겹쳐 띄운다(위아래 꽉 차게, 너비는 그대로 340, 그림자 `--shadow-dialog`, 층 `--z-drag`). 겹쳐도 패널은 모달이 아니다 — 뒤 막 없음, 편집기는 계속 쓸 수 있고, 닫기는 평소대로 `AI` 토글·`✕`·`Ctrl+J`.
  - 그래서 문턱은 사이드바를 **펴면 창 1222px 미만, 접으면 920px 미만**이다(접힌 쪽은 경계 몇 px을 여유로 두어 920). 1100~1221px에서 사이드바와 AI 패널이 둘 다 열려 있으면 겹친다(v0.3까지는 1100 미만에만 걸려 본문이 358~479px로 좁아졌다).
  - 전제: 사이드바 248·AI 패널 340은 **지금 고정값**이다(끌어서 바꾸기는 아직 구현하지 않았다). 너비 끌기를 구현하면 규칙(본문 < 480이면 겹침)은 그대로 두고 문턱만 실제 너비로 다시 계산한다.
- 단축키(전역, **확정**): `Ctrl+N` 새 페이지, `Ctrl+K` 검색, `Ctrl+\` 사이드바, `Ctrl+J` AI 패널, `Ctrl+,` 설정. 트리에서 `F2` 이름 바꾸기, `Del` 휴지통으로 이동.
- 창 닫기(F-05): 저장 대기 내용을 먼저 저장하고 닫는다. 저장이 실패하거나 3초 안에 끝나지 않으면 닫지 않고 S-12를 띄운다(사용자 결정 1-③).

## S-02 페이지 트리

- 행: 높이 28px, 들여쓰기 단계마다 16px, 14px 글자, 2단계 글자색. 왼쪽부터 `펼침 화살표(누르는 영역 24×24, 아이콘 12px)` · `이름` · (AI 전송 제외면 눈 가림 아이콘) · hover 때만 `⋯` `+`(각 24×24, 아이콘 14px).
  - 하위 페이지가 없으면 화살표 자리는 비워 둔다(이름 줄이 맞도록).
  - 이름이 빈 페이지는 "제목 없음"을 3단계 색으로 보인다(F-01.2).
  - 긴 이름은 한 줄 말줄임. hover하면 전체 이름 툴팁.
- **지금 열린 페이지 강조**(F-01): 배경 `--color-bg-selected`(옅은 먹청록) + 글자 1단계 색·굵게. 그 페이지의 조상이 접혀 있으면 열 때 자동으로 펼친다.
- 펼치기·접기: 화살표 클릭, 또는 키보드 →/←. 화살표가 90° 도는 움직임 120ms. 상태는 다시 시작해도 유지(F-01).
- **만들기**(F-01.1): 사이드바 `+ 새 페이지`(최상위 맨 위) 또는 행의 `+`(그 페이지의 하위 맨 위, 부모를 펼침). 새 페이지는 최상위·하위 모두 형제 맨 위에 생긴다(v0.6, P5-3 사용자 요청) — 방금 만든 페이지를 스크롤 없이 바로 본다. 새 페이지가 "제목 없음"으로 생겨 열리고 커서가 페이지 제목에 놓인다.
- **이름 바꾸기**(F-01.2): 맥락 메뉴 "이름 바꾸기" 또는 `F2` → 행 안에서 바로 입력칸(먹청록 테두리). `Enter` 확정, `Esc` 취소, 바깥 클릭 확정. 페이지 제목을 고쳐도 트리에 바로 반영.
- **맥락 메뉴**: 오른쪽 클릭 또는 `⋯`. 항목: 하위 페이지 추가 / 이름 바꾸기 `F2` / 마크다운으로 내보내기 / ─ / AI 전송 제외 ✓ / ─ / 휴지통으로 이동 `Del`(빨강).
- **끌어 옮기기**(F-01.4)
  - 끄는 행은 투명도 45%로 남고, 커서 옆에 이름 고스트(떠 있는 그림자 `--shadow-drag`)가 따라온다.
  - 놓을 위치 표시: 행의 위·아래 1/4 구간이면 **사이**에 놓기 → 2px 먹청록 선(왼쪽 끝 작은 원, 놓일 단계의 들여쓰기에서 시작). 가운데 1/2 구간이면 **안으로**(하위로) 놓기 → 그 행 전체를 옅은 먹청록 + 1px 테두리.
  - 접힌 행 위에 0.6초 머물면 펼친다. 목록 위·아래 끝에 가면 자동 스크롤.
  - 자기 자신과 자기 하위로는 놓을 수 없다: 표시가 나오지 않고 커서가 금지 모양.
  - `Esc`로 끌기 취소.
- 키보드: ↑/↓ 행 이동, →/← 펼침·접힘(또는 부모로), `Enter` 열기, `F2` 이름 바꾸기, `Del` 삭제(S-03), `Shift+F10`/메뉴 키로 맥락 메뉴. ARIA `tree`/`treeitem`/`group`, `aria-expanded`, `aria-selected`.
- 사이드바 아래: `휴지통`(옆에 개수) · `설정`. 휴지통·설정 화면이 열려 있으면 그 행을 강조하고 트리 강조는 끈다.

## S-03 삭제 확인

- 트리·페이지 메뉴의 "휴지통으로 이동" 또는 `Del`.
- 대화상자(420px, 모서리 12px). 제목 `"회의록"을 휴지통으로 옮길까요?`. 하위가 있으면 본문에 `하위 페이지 2개도 함께 옮겨집니다.`(개수 굵게, F-01.3). 이어서 `휴지통에서 언제든 복원할 수 있습니다.`
- 버튼: `취소` / `휴지통으로 이동`(빨강 채움). `Esc` 취소.
- **처음 포커스(v0.2 판단)** — 되돌릴 수 있는지에 따라 나눈다.
  - 되돌릴 수 있는 일(휴지통으로 이동): 위험 버튼 `휴지통으로 이동`에 처음 포커스. `Del` → `Enter` 두 번으로 끝나는 빠른 흐름을 지키고, 실수해도 알림의 `실행 취소`와 휴지통 복원으로 되돌린다.
  - 되돌릴 수 없는 일(영구 삭제·휴지통 비우기 S-04, API 키 삭제 S-08): **`취소`에 처음 포커스**. `Enter`를 습관처럼 눌러도 지워지지 않게 한다. 위험 버튼은 클릭하거나 `Tab`으로 옮겨 누른다. 위험 버튼 모양(빨강 채움)과 위치(오른쪽)는 같다.
- 하위가 없는 페이지도 같은 창을 쓴다(실수 방지. 하위 개수 문장만 뺀다).
- 옮기기 전에 그 페이지의 저장 대기 내용을 먼저 저장한다. 저장이 실패하면 옮기지 않고 알림 `저장하지 못한 내용이 있어 휴지통으로 옮기지 않았습니다. {이유}`(동작 버튼 없음, 위 막대는 S-10 상태).
- 옮긴 뒤: 열려 있던 페이지면 트리의 바로 위 형제(없으면 부모, 없으면 첫 페이지)를 연다. 아래쪽에 알림 `"회의록"을 휴지통으로 옮겼습니다 [실행 취소]`를 5초 보인다(실행 취소 = 바로 복원).

## S-04 휴지통

- 사이드바 `휴지통` → 가운데 영역에 연다(최대 760px).
- 머리: 제목 "휴지통" + 설명 `복원하면 원래 위치로 돌아갑니다. 영구 삭제 전까지 첨부 이미지도 남아 있습니다.` + 오른쪽 `휴지통 비우기`(빨강 글자 버튼).
- 목록 행(지운 시각 최신순): 페이지 이름(굵게) · `하위 n개` 배지 · 아래 줄에 원래 위치 경로(3단계 색) · 지운 날짜 · `복원` `영구 삭제`.

## S-07 AI 패널

- 머리: `AI` · `오늘 12 / 50`(하루 호출/상한, 같은 폭 숫자) · `✕`.
- 작업 탭(세그먼트): `요약` · `다듬기` · `질문`.
  - 요약(F-08.1): 대상 줄 `대상: 선택 영역 · n자` + `요약하기` 버튼. 선택이 없으면 버튼 비활성 + `본문에서 요약할 부분을 선택하세요`. 결과 카드 버튼 `삽입` · `복사`(D-30 ⑤). `바꾸기`는 없다(요약으로 원문을 덮지 않는다).
  - 다듬기(F-08.2): 결과 카드에 `원문`(2단계 색)과 `다듬은 글`을 위아래로 나란히. 버튼 `바꾸기`(주 버튼) · `삽입` · `복사`. `바꾸기`는 다듬기에만 있다(D-30 ⑤).
  - 질문(F-08.3): 대상 줄 `대상: 이 페이지 전체 · n자`(선택 영역이면 `대상: 선택 영역 n자`). 페이지가 20,000자를 넘고 선택이 없으면 `대상: 이 페이지 전체 · n자 (20,000자 넘음)`(v0.6, pm 결정) — 아래 상태 알림 5와 함께 왜 보낼 수 없는지를 대상 줄에서도 보인다. 질문은 오른쪽 말풍선(옅은 회색), 답은 왼쪽 그냥 글 + `삽입` `복사`. 아래 입력창(여러 줄, `Enter` 보내기 / `Shift+Enter` 줄바꿈), 아래 줄 왼쪽 안내, 오른쪽 `새 대화`. 받는 중에는 점 3개 표시 + 보내기 자리에 `중지`.
  - 앞 대화를 뺐을 때: 대화 맨 위에 `앞 대화 n개는 이번 질문에 포함되지 않음`(3단계 색, 가운데).
- 결과를 반영하기 전에는 본문이 바뀌지 않는다. `바꾸기`·`삽입` 후 `Ctrl+Z`로 되돌린다(F-08).
- **끝난 이유(v0.3, D-31)**: 정상 완료는 `stopReason`이 `end_turn`·`stop_sequence`일 때뿐이다(계약-AI 4절). 그 밖의 값으로 끝나면 결과(질문 탭은 그 답) 아래에 배지 + 이유 문구를 한 줄로 보인다(12px, 2단계 색, 배지는 `--color-bg-sunken` 바탕·3단계 이상 글자).

  | 끝남 | 배지 | 문구 |
  |---|---|---|
  | 출력 상한(`max_tokens`) | `잘림` | `출력 상한에 걸려 결과가 잘렸습니다.` |
  | 거부(`refusal`) | `끝나지 않음` | `AI가 이 요청에 답하지 않았습니다.` |
  | 문맥 초과(`model_context_window_exceeded`) | `끝나지 않음` | `문맥 한도를 넘어 결과가 끝까지 만들어지지 않았습니다.` |
  | 그 밖의 값·`unknown` | `끝나지 않음` | `결과가 정상으로 끝나지 않았습니다.` |

  - 이어서 결과 글이 있으면 `노트에 넣을 수 없어 복사만 할 수 있습니다.`, 글이 비었으면 `노트는 바뀌지 않았습니다.`(이때는 버튼 줄도 없다).
  - **세 탭 모두 같게(pm 결정)**: 요약·다듬기·질문 어느 탭이든 정상 완료가 아니면 `바꾸기`·`삽입`을 끄고(비활성, 자리는 남김) `복사`만 쓸 수 있다. `잘림`도 여기에 든다.
  - `중지`로 끊은 결과(`중지했습니다`)와 호출 실패(빨강 알림)는 끝난 이유가 아니라 지금 규칙대로다.
- 상태 알림(패널 본문 위, 한 번에 하나, 우선순위 순). 이 상태에서는 작업 버튼·입력창이 비활성.
  1. **API 키 없음**(F-08.6): 회색 알림 + `설정 열기`.
  2. **AI 전송 제외 페이지**(F-08.5): 회색 알림, 입력창 자리표시 `AI 전송 제외 페이지입니다`.
  3. **오프라인**(F-08): 노랑 알림 `인터넷에 다시 연결되면 자동으로 켜집니다.` 머리의 사용량 자리에 `오프라인` 배지.
  4. **오늘 상한 도달**(F-08.5): 노랑 알림 + 남은 시간.
  5. **2만 자 초과**(F-08.3, F-08.5): 회색 알림 `질문할 부분을 본문에서 선택하세요. 자동으로 잘라 보내지 않습니다.`
  - 호출 실패(시간 초과·네트워크·키 오류): 결과 자리에 빨강 알림 + 이유 + `노트는 바뀌지 않았습니다.` + `다시 시도`.
  - 크레딧 소진: 빨강 알림 `이번 달 크레딧 소진`(F-08).
- 페이지를 바꾸면 그 페이지의 대화로 바뀐다(F-08.3).

## S-08 설정

- 사이드바 `설정` 또는 `Ctrl+,` → 가운데 영역(최대 760px). 위에 구역 탭 `일반` `AI`(한 화면 스크롤로도 다 보이는 길이라 탭은 위치 이동만 한다).
- 행 배치: 왼쪽 200px 이름, 오른쪽 조작 + 도움말(12px, 3단계 색).
- `일반` 구역 순서(v0.5): 화면(테마 → 강조색) → 데이터.
- 화면 › 테마: 세그먼트 `Windows 설정 따름`(기본) · `라이트` · `다크`. 바꾸면 바로 적용(`<html data-theme>`, `ui_state.theme`).
- 화면 › 강조색(v0.5, P5-2): 동그란 색 견본 5개를 한 줄로 + 오른쪽에 고른 이름.
  - 순서와 이름: `먹청록`(기본) · `남색` · `자주` · `주황 갈색` · `회색`. 오른쪽 이름은 13px 2단계 색, 기본이면 `먹청록 (기본)`.
  - 견본: 지름 20px 원을 24×24 누르는 영역 가운데에 둔다, 사이 8px. 채움은 그 프리셋의 지금 모드(라이트·다크) `--color-accent` 값. 테두리 없음.
  - 선택 표시: 고른 견본 안에 `Check`(lucide, 12px, 선 2) — 색은 그 프리셋의 `--color-text-on-accent`. 바깥 고리는 쓰지 않는다(포커스 고리와 겹치지 않게). 색만으로 구별하지 않도록 체크 모양이 선택을 말한다.
  - 마우스를 올리면 툴팁으로 이름. 접근성: `role="radiogroup"`(이름 `강조색`), 견본은 `role="radio"` + `aria-checked` + `aria-label`(이름). `←/→`로 옮기며 바로 고른다(라디오 규칙), `Tab`은 묶음 하나로 들어오고 나간다.
  - 미리보기 없음: 고르면 바로 앱 전체에 적용한다(`<html data-accent>`, `ui_state.accent`). 마음에 안 들면 다른 견본을 누르면 되므로 따로 미리보기·확인 버튼을 두지 않는다. 행 오른쪽 `저장됨` 1.5초는 다른 설정과 같다.
  - 바뀌는 것은 강조 토큰 7개뿐(아래 "강조색 프리셋"). 포커스 고리·상태색(위험·경고·성공)·코드 강조·검색 강조는 그대로다.
- 데이터(NF-01): 설명 `노트·이미지·설정이 모두 이 폴더 하나에 있습니다. 앱을 끈 뒤 폴더를 통째로 복사하면 백업입니다.` 경로는 고정폭 글자로 회색 바탕 상자(긴 경로는 말줄임 + 툴팁) + `폴더 열기`(탐색기).
- AI › Claude API 키(F-08.6)
  - 키 없음(v0.3, D-30 ⑦): 입력칸(`password`, 자리표시 `sk-ant-로 시작하는 키 붙여넣기`) + 주 버튼 하나 `확인하고 저장`(시험 호출을 통과하면 바로 저장, `set_api_key`). 붙여넣기 전에는 비활성, 붙여넣으면 활성, `Enter`로도 누른다. 누르면 버튼 글자가 `확인하는 중…`으로 바뀌고 입력칸·버튼이 잠긴다. 도움말 `붙여넣은 키로 짧은 시험 호출을 해서 통과하면 Windows 자격 증명 관리자에 저장합니다.` 오프라인이면 버튼 비활성 + 도움말 `오프라인에서는 확인할 수 없습니다`. 확인만 하고 저장하지 않는 동작은 없다.
  - 성공하면 아래 "키 있음" 모양으로 바뀐다.
  - 확인 실패: 입력칸 아래 빨강 글 `키를 확인하지 못했습니다: 잘못된 키입니다.`
  - 키 있음: `🔑 ••••••••••••7Qx2`(끝 4자리만) + `확인됨` + `바꾸기` · `삭제`(빨강 글자). `바꾸기`는 키 없음과 같은 입력칸 + `확인하고 저장` + `취소`를 연다(통과하기 전에는 원래 키를 그대로 둔다). 삭제는 확인 창(S-03 모양, 제목 `API 키를 삭제할까요?`, 본문 `자격 증명 관리자에서 지웁니다. 다시 쓰려면 키를 새로 붙여넣어야 합니다.`, 버튼 `취소` / `삭제`, 처음 포커스 `취소`).
- AI › 하루 호출 상한(F-08.5): 숫자 입력(88px, 오른쪽 정렬) `회 · 오늘 12회 사용`. 1~1000.
- AI › 한 번에 보내는 글자 수: `최대 20,000자`(바꿀 수 없음, 기능정의 F-08.5는 호출 상한만 바꿀 수 있게 정함).
- AI › 사용 기록: 표(날짜 · 호출 · 보낸 글자), 최근 30일. `노트 내용은 기록하지 않습니다.`
- 저장 버튼 없음. 바꾸면 바로 저장하고 행 오른쪽에 `저장됨`을 1.5초 보인다.

## S-12 저장 못 한 채 닫기

- 창을 닫을 때(제목 표시줄 ✕, `Alt+F4`) 저장이 실패하거나 3초 안에 끝나지 않으면 창을 닫지 않고 이 대화상자를 띄운다(F-05, 사용자 결정 1-③). S-03과 같은 모양(420px, 모서리 12px, `alertdialog`).
- 제목 `저장하지 못한 내용이 있습니다`
- 본문(이유에 따라 첫 문장만 바뀜)
  - 실패: `{이유}.` 예) `디스크 공간이 부족합니다.`
  - 3초 넘음: `저장이 끝나지 않았습니다.`
  - 이어서 `그래도 닫으면 마지막 저장 뒤에 입력한 내용은 사라집니다.` 그 아래 저장 못 한 페이지 이름 목록(최대 3개, 넘으면 `외 n개`, 2단계 색). **한 페이지만 실패해도 이름을 보인다(v0.4)** — 그래도 닫기 전에 어느 페이지 내용을 따로 옮겨 둘지 알아야 하기 때문이다. 이름이 빈 페이지는 `제목 없음`.
- 버튼(오른쪽 정렬): `그래도 닫기`(빨강 글자 버튼) · `다시 저장`(주 버튼, **처음 포커스**). 안전한 쪽이 주 버튼이고 처음 포커스다.
  - `다시 저장`: 버튼에 진행 표시(폭 유지). 성공하면 바로 창을 닫는다. 또 실패하면 창에 남아 본문 첫 문장을 새 이유로 바꾼다.
  - `그래도 닫기`: 저장하지 않고 닫는다.
  - `Esc`·바깥 클릭: 대화상자만 닫고 앱은 그대로(닫기 취소). 위 막대는 S-10 상태를 계속 보인다.

## S-13 넣지 않은 이미지·링크 알림

모두 공통 알림(토스트, 화면 아래 가운데, 5초). 붙여넣기·끌어 놓기·파일 선택 한 번에 알림 하나로 합친다. 넣은 것은 넣고, 넣지 않은 것만 알린다.

| 경우 | 문구 | 동작 버튼 |
|---|---|---|
| 붙여넣은 글 속 원격 이미지(`http(s)://`) (2-①) | `외부 이미지 n개는 넣지 않았습니다.` | 없음 |
| SVG 파일 (2-②) | `SVG 이미지는 넣을 수 없습니다. PNG로 바꿔 넣으세요.` | 없음 |
| 20MB 초과 (2-②) | `20MB가 넘는 이미지는 넣지 않았습니다: {파일 이름}` | 없음 |
| 허용 밖 형식(bmp·ico·heic 등) (2-②) | `넣을 수 없는 형식입니다: {파일 이름}. PNG·JPG·GIF·WebP만 넣을 수 있습니다.` | 없음 |
| 저장 실패(디스크·다른 프로그램 등) | `이미지를 저장하지 못했습니다({이유}). 그 이미지를 다시 넣어 보세요.` `{이유}`는 아래 "저장 실패 이유 문구" | 없음 |
| 여러 개 중 일부만 | `이미지 n개 중 m개를 넣었습니다. {이유별 개수}는 넣지 않았습니다.` 예) `이미지 4개 중 2개를 넣었습니다. SVG 1개, 20MB 초과 1개는 넣지 않았습니다.` | 없음 |
| 모두 못 넣음, 이유가 둘 이상(v0.3) | `이미지 n개를 넣지 않았습니다: {이유별 개수}.` 예) `이미지 3개를 넣지 않았습니다: SVG 1개, 20MB 초과 2개.` | 없음 |
| 이미지를 저장할 곳이 없음(열린 페이지가 없는 등, v0.3) | `이미지를 저장할 곳이 없어 넣지 않았습니다.` | 없음 |
| 링크 복사 (2-③) | `링크를 복사했습니다` | 없음 |
| 링크 복사 실패(클립보드 오류, v0.3) | `링크를 복사하지 못했습니다.` | 없음 |

- 문구 규칙: 무엇을 안 했는지 + 몇 개/어느 파일 + 할 수 있는 일. 파일 이름이 길면 가운데 말줄임(앞 16자…확장자).
- 문구 조각(v0.3, P3-5 구현에서 정함)
  - `{이유별 개수}`의 이유 이름: `외부 이미지` · `SVG` · `20MB 초과` · `넣을 수 없는 형식` · `저장 실패`. 쉼표로 잇고, 외부 이미지가 맨 앞, 나머지는 파일을 살펴본 순서다.
  - `{파일 이름}`이 셋 이상이면 앞의 두 개만 쓰고 `외 n개`를 붙인다. 예) `20MB가 넘는 이미지는 넣지 않았습니다: 사진1.png, 사진2.png 외 3개`
  - 이름이 없는 파일은 `이름 없는 파일`. 붙여넣은 `data:` 이미지는 `붙여넣은 이미지.png`(확장자는 형식대로)로 이름 붙인다.
  - 저장 실패의 `{이유}`를 알 수 없으면 `알 수 없는 오류`.
- `data:` 이미지(글 속에 들어 있는 그림)는 첨부로 저장해 넣는다. 알림 없음.
- 이유가 여럿이고 두 줄을 넘으면 `이미지 4개 중 2개를 넣었습니다. 2개는 넣지 않았습니다.`로 줄인다.
- 알림은 `role="status"`(읽기 프로그램이 끊지 않고 읽음).
- 알림이 겹칠 때는 공통 규칙 "알림(토스트)"의 우선순위를 따른다(v0.5). `휴지통으로 옮겼습니다 [실행 취소]`가 떠 있는 동안 이 절의 알림이 오면 그 알림이 닫힌 뒤에 뜬다.

### 저장 실패 이유 문구(v0.5)

데이터 파일에 쓰지 못했을 때의 `{이유}`. S-10 띠, S-12 본문 첫 문장, 위 표의 이미지 저장 실패, 휴지통 이동 거절 알림에 같은 문구가 들어간다. 문구는 `src/api/index.ts`(`errorReason`) 그대로다.

| 오류 종류 | 언제 | `{이유}` 문구 | 화면 동작 |
|---|---|---|---|
| `Db` | 디스크 가득 참 등 DB 쓰기 실패 | `데이터베이스에 쓰지 못했습니다(디스크 공간을 확인하세요)` | 편집 내용을 메모리에 두고 5초마다 다시 저장(S-10) |
| `DbBusy` | 백업·동기화 등 다른 프로그램이 데이터 파일을 잡고 있어 5초 안에 쓰지 못함(P4-6, 사용자 결정 0850, 계약-DB 3절) | `다른 프로그램이 데이터 파일을 쓰는 중입니다(백업·동기화 프로그램을 확인하세요)`(사용자 결정 카드 20261027-2355) | `Db`와 같다. 띠·`지금 다시 저장`·5초마다 다시 저장 |
| `Io` | 첨부 파일 읽기·쓰기 실패 | `파일을 읽거나 쓰지 못했습니다` | `Db`와 같다 |

- `DbBusy`는 잠깐 지나가는 일이 많다. 다른 프로그램이 파일을 놓으면 다음 다시 저장(5초 뒤)에서 띠가 저절로 사라진다. 사용자가 할 일은 괄호 안 안내(백업·동기화 프로그램 확인)뿐이다.

## 공통 규칙

- **포커스(v0.5, P5-1)**: 모든 조작 요소에 `:focus-visible` 2px 하늘색 테두리(`--color-focus-ring`, 2px 띄움). 입력칸은 테두리 색이 포커스 색으로 바뀌고 1px 바깥선. 먹청록(강조색)은 선택·지금 위치에 남기고 포커스에는 쓰지 않는다 — 선택된 트리 행에 키보드 포커스가 있어도 둘이 구별된다.
- **누르는 영역(v0.2, 사용자 결정 4-③)**: 기준은 24 × 24px(`--hit-target-min`, WCAG 2.2 AA 2.5.8). 44px(AAA)은 쓰지 않고 이 문서의 디자인 크기(트리 행 28, 버튼 30, 작은 버튼 26, 아이콘 버튼 24)를 따른다. 구현에서 44px로 키운 곳(/ 메뉴 항목·도구 막대 버튼)은 이 문서 크기로 되돌린다.
  - 보이는 모양이 24px보다 작은 것은 누르는 영역만 24px로 넓힌다(투명 여백 또는 `::before`): 트리 펼침 화살표, 체크리스트 네모, 경로(위 막대) 링크.
  - 24px로 키운 것: 트리 행의 `⋯` `+`(22→24), 블록 손잡이(22×24→24×24), 코드 언어 선택(22→24), AI 패널 `새 대화`(22→24), 표 `+` 띠(16→24).
  - 글 속 링크는 기준의 예외(WCAG 2.5.8 "문장 안" 예외).
- **상태**: 버튼은 기본 · hover(바탕 6% 어둡게) · 눌림(10%) · 비활성(글자 38% 투명, 커서 금지) · 진행 중(글자 대신 작은 진행 표시, 폭 유지).
- **알림(토스트)**: 화면 아래 가운데, 진한 바탕(본문 글자색) + 밝은 글자, 동작 버튼 0~1개, 5초. 최대 폭 560px, 두 줄까지. 편집기 안의 알림(S-13)도 같은 모양이다.
  - **한 번에 하나, 우선순위(v0.5, pm 결정)**: 동작 버튼이 있는 알림(`실행 취소`·`열기`·`폴더 열기` 등)이 떠 있는 동안에는 일반 알림(버튼 없음)으로 바꾸지 않는다. 일반 알림은 그 알림이 닫힌 뒤에 띄운다. 되돌릴 기회를 다른 알림이 덮어 없애지 않게 하기 위해서다.
  - 기다리는 일반 알림이 여럿이면 마지막 것만 띄운다. 새 알림이 동작 버튼 알림이면 지금 것을 바꾼다(마지막 동작이 되돌릴 대상). 그 밖에는 겹치면 마지막 것만.

- 비용과 조건
  - 화면 점검이 두 배가 된다 → QA는 라이트 전부 + 다크는 S-01·S-05·S-06·S-07만 확인하는 것으로 제안.
  - 프론트 규칙: 색 값(#hex, rgb) 직접 쓰기 금지, 이미지·아이콘은 `currentColor`.
  - 앱 창 배경이 흰색으로 번쩍이지 않게 Tauri 창 `backgroundColor`(또는 첫 HTML 배경)를 테마에 맞춘다 — 프론트·백엔드가 구현 때 확인.
