### D-05 AI는 Claude API를 쓰는 부가 기능, 비용은 Max 플랜 월간 API 크레딧
- 결정일: 2026-10-25 (아이디어 노트 2절·5절)
- 결정: AI 어시스트는 Claude API로 만든다. 비용은 Claude Max 플랜에 포함된 월간 API 크레딧으로 충당한다. AI는 부가 기능이며, 앱의 기본 동작은 AI 없이 완결된다. 모델은 가벼운 작업에 `claude-haiku-5-5`, 긴 노트 분석·글쓰기에 `claude-sonnet-5-5`를 쓴다.
- 근거: 아이디어 노트 2절(Claude API, Max 플랜 크레딧)과 5절(모델 선택, 동작 원칙).
- 참고(아이디어 노트 2절의 사실): 크레딧을 받으려면 Claude Console 조직을 플랜에 연결해야 하고, 연결한 조직은 나중에 직접 바꿀 수 없다. 이 크레딧은 Claude 앱·Claude Code 사용 한도와 별개다. 소진되면 다음 월간 지급 때까지 API 요청이 멈춘다. 금액·만료일은 Console의 Billing > Promotional credits에서 확인한다.
- 대안: 로컬 LLM, 다른 회사 API, 종량 결제. 아이디어 노트에서 검토하지 않았다.
- 관련: F-08, NF-05, D-09

### D-06 저장 방식: SQLite만 사용
- 결정일: 2026-10-26 (사용자 결정, 카드 20261026-0014-NOTE-pm-p0-tech)
- 결정: 페이지 트리·본문·설정·AI 사용 기록을 로컬 SQLite 파일 하나에 저장한다. 본문은 TipTap JSON으로 저장한다. 이미지는 데이터 폴더의 첨부 폴더에 파일로 둔다. 이식성은 마크다운 내보내기(F-06)로 확보한다.
- 근거: SQLite는 전문 검색 색인(FTS5)·트리 순서·후순위 DB 뷰(F-20)에 유리하고 트랜잭션으로 원자적 저장이 쉽다. 사용자 1명이 앱 안에서만 편집하므로(D-03) 마크다운 원본의 외부 편집기 호환 이득이 작다. 병행보다 동기화 코드가 적다.
- 대안: 마크다운 파일만(이식성 최고, 검색·트리 순서·외부 수정 충돌 처리가 부담), 병행(마크다운 원본 + SQLite 색인. 두 장점을 얻지만 동기화·색인 재구축 경로가 늘어남).
- 대가: 데이터를 다른 앱에서 바로 열 수 없다. 이식은 내보내기를 거쳐야 하며 내보내기 변환 품질(F-06)에 기댄다.
- 관련: Q-03, F-01, F-02.6, F-04, F-05, F-06, NF-01, NF-02, NF-03

### D-07 앱 셸: Tauri (조건부, 실패 시 Electron)
- 결정일: 2026-10-26 (사용자 결정, 카드 20261026-0014-NOTE-pm-p0-tech)
- 결정: 앱 셸은 Tauri로 하고 UI는 React로 만든다. 조건: 본 개발 전에 시험 빌드로 이 PC에서 무리 없이 빌드·실행되는지 먼저 확인한다. 안 되면 Electron으로 간다(그때는 새 D 번호로 기록). Rust·MSVC 빌드 도구는 사용자가 설치한다. (2026-10-26 보완: 시험 빌드 통과로 조건 충족, Tauri 유지 → D-12)
- 근거: Tauri는 시스템 WebView2를 써서 앱 용량과 실행 메모리가 작다(아이디어 노트 6절). 앱을 매일 켜 두므로 실행 메모리 부담이 크다. 이 PC는 RAM 16GB에서 개발 세션 여러 개가 함께 돈다(2026-10-26 확인 시점 여유 약 7.6GB). WebView2 런타임(155.0.4283.62)이 이미 설치되어 있다(2026-10-26 확인).
- 대안: Electron(Chromium을 내장해 실행 메모리·용량이 큼. Node/JS만으로 개발할 수 있고 자료가 가장 많음).
- 대가: Rust 툴체인과 MSVC가 필요하다. 첫 빌드가 무겁고 느려 병렬 세션과 메모리를 다툰다. 자료는 Electron보다 적다.
- 관련: Q-01, NF-01, NF-04, NF-05

### D-08 편집기 라이브러리: TipTap
- 결정일: 2026-10-26 (사용자 결정, 카드 20261026-0014-NOTE-pm-p0-tech. 기획 추천안은 BlockNote였으나 사용자가 TipTap을 골랐다)
- 결정: 블록 편집기는 TipTap(ProseMirror 기반)으로 만든다. 공개 npm의 MIT 패키지만 쓰고 유료(Pro·Cloud) 기능은 쓰지 않는다.
- 근거: 사용자 선택. TipTap은 유연하고 확장 자료가 많다. 2026-10-26 확인 결과, 필요한 확장(블록 손잡이, 제안 메뉴 기반 suggestion, 표, 코드, 이미지, 체크리스트, 마크다운)이 공개 npm에서 모두 MIT다(기능정의 "TipTap 확장 확인" 메모).
- 대안: BlockNote(Notion식 블록·/ 메뉴·블록 끌기 기본 제공, 틀 밖 변경이 어려움), Lexical(가볍지만 블록 UI·마크다운 변환을 더 직접 만들어야 함).
- 대가: 블록 손잡이·/ 메뉴·블록 이동 UI를 직접 만들어야 한다. TipTap 공식 / 메뉴는 패키지가 없는 실험 예제라(공식 문서 "This extension does not have a published package yet") 예제 코드를 가져와 직접 유지한다.
- 관련: Q-02, F-02, F-02.7, F-03, F-06

### D-15 SQLite 연결 방식: Rust rusqlite + Tauri 명령
- 결정일: 2026-10-26 (사용자 결정, 카드 20261026-0105-NOTE-pm-p1-sqlite)
- 결정: SQLite는 Rust 쪽에서 `rusqlite`(`bundled` 기능, SQLite를 함께 빌드)로 연다. 화면은 Tauri 명령(`invoke`)만 부르고, SQL은 Rust 한곳에 둔다.

- 대안: 직접 그린 SVG 아이콘 / Pretendard 포함 / 단축키·크기 일부 바꾸기 / 모두 44px / 테스트 때 실제 데이터 폴더 이름을 바꿔 보관했다 되돌리기.
- 대가: npm 의존성 1개가 늘어난다. 화면설계 목업과 글자 모양이 조금 다르다. 창을 900px보다 좁게 줄일 수 없다. 터치 화면에선 누르기 어렵다. backend1의 작은 코드 변경과 릴리스에서 환경 변수가 무시되는지 확인이 든다.
- 관련: D-03, D-14, F-01, F-02.7, NF-01, NF-04, NF-06

### D-23 블록 손잡이(F-02.7) 직접 구현
- 결정일: 2026-10-26 (pm 결정)
- 결정: F-02.7 블록 손잡이는 `@tiptap/extension-drag-handle`·`-react`를 쓰지 않고 직접 만든다(`src/editor/BlockHandle.tsx`).
- 근거: `@tiptap/extension-drag-handle` 3.32.0의 peerDependencies에 `@tiptap/y-tiptap`·`@tiptap/extension-collaboration`·`@tiptap/extension-node-range`가 있고 선택(optional) 표시가 없다. 그 peer가 다시 `yjs`·`y-protocols`를 요구한다. 그래서 손잡이 하나를 위해 협업용 패키지 5개를 더 설치해야 한다(npm 레지스트리, 2026-10-26 확인). 실시간 협업은 후순위(F-23)이고 무거운 의존성은 NF-04에 부담이다.
- 대안: `@tiptap/extension-drag-handle-react`와 협업 peer를 함께 설치.
- 대가: 손잡이 위치 계산·끌어 놓기를 직접 유지한다.
- 관련: D-08, D-11, D-24, F-02.7, F-23, NF-04

### D-24 Tauri 창 `dragDropEnabled: false`
- 결정일: 2026-10-26 (pm 결정)
- 결정: `tauri.conf.json`의 창 설정 `dragDropEnabled`를 `false`로 둔다.
- 근거: 블록 손잡이(F-02.7)·트리 끌어 옮기기(F-01.4)·이미지 끌어 놓기(F-02.6)는 화면의 HTML5 끌어 놓기를 쓴다. Tauri 문서: 이 처리기를 끄는 것은 "required to use HTML5 drag and drop APIs on the frontend on Windows since we replace the drag drop handler of WebView2"(https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html `disable_drag_drop_handler`). 지금 설정에 반영되어 있다(2026-10-26 확인).
- 대안: 켜 두고 Tauri `DragDropEvent`로 파일 끌어 놓기를 Rust에서 받기.
- 대가: Tauri `DragDropEvent`(끌어 온 파일의 경로)를 쓸 수 없다. 탐색기에서 끌어 온 이미지도 화면의 HTML5 `drop`으로 받는다.
- 관련: D-23, F-01.4, F-02.6, F-02.7

### D-25 마크다운 내보내기(F-06) 직접 변환기
- 결정일: 2026-10-26 (pm 결정)
- 결정: TipTap JSON → 마크다운 변환은 직접 만든 변환기(`src/export/markdown.ts`)로 한다. `@tiptap/markdown`·`marked`는 넣지 않는다.
- 근거: 내보내기는 한 방향이라 마크다운 파서가 필요 없다. `@tiptap/markdown`은 공식 문서 기준 "early release"이고 표 셀마다 자식 노드 1개만 지원한다(기능정의 F-06 구현 메모). 의존성을 늘리지 않는다(NF-04). `package.json`에 두 패키지가 없다(2026-10-26 확인).
- 대안: `@tiptap/markdown` 쓰고 빠진 규칙만 직접 더하기.
- 대가: F-02.1~F-02.6 블록의 변환 규칙을 직접 유지한다. 블록 종류를 늘리면 변환기도 고친다.
- 관련: D-06, D-08, F-06, NF-04

### D-26 capabilities에 `core:window:allow-destroy` 추가
- 결정일: 2026-10-26 (pm 결정)
- 결정: 창 닫기 직전 저장(F-05)을 위해 `capabilities/default.json`에 `core:window:allow-destroy`를 더한다.
- 근거: 화면은 Tauri `onCloseRequested`로 닫기 요청을 받아 저장을 기다린다. 이 함수는 처리기가 끝나면 스스로 `destroy()`를 불러 창을 닫으므로 그 권한이 필요하다. 권한이 없으면 창이 닫히지 않아 지금은 닫기 저장을 꺼 두었다(`src/app/AppShell.tsx` `CLOSE_SAVE_ENABLED = false`, 2026-10-26 확인). 권한은 창 없애기 하나만 더한다.
- 대안: Rust에서 닫기 이벤트를 막고 저장 끝을 기다려 닫기(화면 저장 대기열을 Rust가 알아야 함).
- 대가: 화면이 창을 없앨 수 있는 권한이 하나 는다.
- 관련: D-19, F-05
