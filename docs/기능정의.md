## F-01 페이지 트리 — MVP

- 설명: 왼쪽 사이드바에 페이지를 중첩 트리로 보여 준다. 페이지 안에 하위 페이지를 둘 수 있다(아이디어 노트 4절 "폴더 또는 중첩 페이지" 중 중첩 페이지로 정리. 폴더와 페이지를 따로 두지 않고 모든 노드가 페이지다).
- 사용자 동작: 트리 항목을 클릭하면 그 페이지가 편집 영역에 열린다. 하위 페이지가 있는 항목은 펼치기·접기를 한다.
- 완료 기준
  - 트리에서 페이지를 클릭하면 1초 안에 그 페이지 본문이 편집 영역에 보인다.
  - 하위 페이지를 3단계 이상 중첩해 만들고, 펼치기·접기 상태가 앱을 다시 시작해도 유지된다.
  - 지금 열린 페이지가 트리에서 강조 표시된다.
- 오프라인 동작: 전부 동작한다.
- 저장 형태(D-06): 페이지 테이블의 부모 ID 열과 형제 간 순서 열로 트리를 표현한다.

### F-01.1 페이지 만들기 — MVP(사용자 확정, 2026-10-26)
- 사용자 동작: 사이드바의 "새 페이지" 버튼, 또는 트리 항목의 "하위 페이지 추가".
- 완료 기준: 새 페이지가 "제목 없음"으로 생기고 바로 열리며 제목에 커서가 놓인다. 새 페이지는 형제 가운데 맨 위(첫 자리)에 생기고 기존 형제는 한 칸씩 아래로 밀린다. 최상위·하위 페이지 모두 같다(D-46). 하위 페이지로 만들면 부모 아래 맨 위에 보인다. 앱을 다시 시작해도 남아 있다.
- 오프라인 동작: 전부 동작한다.

### F-01.2 페이지 이름 바꾸기 — MVP(사용자 확정, 2026-10-26)
- 사용자 동작: 페이지 상단 제목을 고치거나 트리 항목에서 "이름 바꾸기".
- 완료 기준: 바꾼 이름이 트리·편집 영역·검색 결과에 같게 보인다. 빈 이름은 "제목 없음"으로 보인다. 같은 부모 아래 이름이 겹쳐도 두 페이지 모두 남는다(페이지는 ID로 구분한다).
- 오프라인 동작: 전부 동작한다.

### F-01.3 페이지 삭제·휴지통·복원 — MVP(사용자 확정, 2026-10-26)
- 사용자 동작: 트리 항목에서 "삭제" → 확인 창. 사이드바의 "휴지통"에서 "복원" 또는 "영구 삭제"·"휴지통 비우기".
- 완료 기준: 하위 페이지가 있으면 확인 창에 하위 페이지 수를 보여 주고, 확인하면 하위까지 함께 휴지통으로 간다. 휴지통 목록은 항목마다 원래 위치(트리 경로)를 보여 준다(D-19). 휴지통에서 복원하면 원래 부모·순서 위치로 돌아온다(원래 부모가 영구 삭제되었거나 아직 휴지통에 있으면 최상위 맨 끝으로). 영구 삭제 전에는 데이터와 첨부 이미지가 남는다. 첨부 파일은 영구 삭제 때 정리한다(D-17).
- 오프라인 동작: 전부 동작한다.

### F-01.4 페이지 이동 — MVP(사용자 확정, 2026-10-26)
- 사용자 동작: 트리 항목을 끌어 다른 페이지 아래나 사이로 놓는다.
- 완료 기준: 놓은 위치로 부모·순서가 바뀌고 다시 시작해도 유지된다. 자기 하위 페이지 안으로는 놓을 수 없다.
- 오프라인 동작: 전부 동작한다.

## F-02 블록 편집 — MVP

- 설명: 페이지 본문을 블록 단위로 편집한다(Notion 방식). 블록 종류는 아이디어 노트 4절을 따른다. 기본 블록은 문단이다. TipTap으로 만든다(D-08).
- 사용자 동작: 타이핑으로 입력한다. 빈 줄에서 `/`를 쳐 블록 종류 메뉴를 열거나, 마크다운 단축 입력(`# `, `- `, `[] `, 백틱 3개)으로 바꾼다.
- 완료 기준(공통): 각 블록을 키보드만으로 만들 수 있다. 저장 후 다시 열었을 때 블록 종류와 내용이 그대로다.
- 오프라인 동작: 전부 동작한다.
- 링크(D-20): 노트 안 링크를 클릭해도 열지 않는다. 오른쪽 클릭 "링크 복사"로 주소를 복사한다. `@tiptap/extension-link` 없이 직접 구현한다(D-32).
- 도구 막대(D-54): 편집기에서 쓸 수 있는 서식을 모두 아이콘 버튼으로 보인다. 블록 종류(본문·제목 1·2·3·글머리·번호 목록·체크리스트·코드 블록·인용), 글자 서식(굵게 Ctrl+B·기울임 Ctrl+I·밑줄 Ctrl+U·취소선 Ctrl+Shift+S·인라인 코드 Ctrl+E), 정렬(F-02.8), 넣기(표·이미지·구분선), 실행 취소·다시 실행을 묶음으로 나눠 위계가 보이게 둔다. 표 행·열 도구는 도구 막대에 두지 않고 표에 붙여 띄운다. 코드 언어 고르기(D-53)는 도구 막대 맨 오른쪽 끝에 커서가 코드 블록 안일 때만 보인다(D-58). 묶음·순서·아이콘은 화면설계 S-06.
  - 완료 기준: 위 서식마다 아이콘 버튼이 있고, 이름(`aria-label`)과 툴팁(단축키 또는 마크다운 입력 안내)이 있다. 커서 자리의 서식이 켜져 있으면 버튼이 눌린 상태(`aria-pressed`)로 보인다. 쓸 수 없는 자리에서는 버튼이 꺼진다(사라지지 않는다). 버튼으로 준 서식과 단축키로 준 서식이 같은 결과로 저장된다. 링크 만들기 버튼은 없다(D-32).
- 글자 스타일(D-52): 편집 본문 글자 크기·줄 간격·자간·블록 간격은 v0.2.0과 같다(본문 14px·줄 간격 1.45, 제목·문단 크기와 위아래 여백은 WebView2 기본값, 체크리스트 항목 사이 1em). 본문 최대 폭은 D-49를 따른다.
- 구현 메모(D-08): `/` 메뉴는 `@tiptap/suggestion`(MIT)으로 직접 만든다. TipTap 공식 slash commands는 패키지가 없는 실험 예제다. 아래 "TipTap 확장 확인"을 본다.

## F-03 실행 취소·다시 실행 — MVP(사용자 확정, 2026-10-26)

- 설명: 편집 영역에서 한 편집을 되돌리고 다시 적용한다.
- 사용자 동작: Ctrl+Z(실행 취소), Ctrl+Y 또는 Ctrl+Shift+Z(다시 실행).
- 완료 기준
  - 텍스트 입력·삭제, 블록 종류 변경, 블록 이동, 표 행·열 변경, 찾아 바꾸기('바꾸기' 한 번·'모두 바꾸기' 한 번이 각각 한 단계, F-11)를 각각 되돌릴 수 있다.
  - 자동 저장(F-05)이 일어난 뒤에도 실행 취소가 된다. 되돌린 상태도 자동 저장된다.
  - 실행 취소 기록은 페이지마다 따로 둔다. 앱을 다시 시작하면 기록은 비어도 된다.
  - 페이지 삭제의 되돌리기는 실행 취소가 아니라 휴지통 복원(F-01.3)으로 한다. Ctrl+Z는 편집기 안의 본문 편집만 되돌리고 페이지 삭제는 되돌리지 않는다. 삭제 알림의 [실행 취소] 버튼은 휴지통 복원을 바로 부른다(D-28).
- 오프라인 동작: 전부 동작한다.
- 구현 메모: StarterKit의 UndoRedo(ProseMirror history). 페이지마다 기록을 따로 두려면 페이지 전환 때 에디터 상태를 페이지별로 보관해야 한다.

## F-04 전체 텍스트 검색 — MVP

- 설명: 모든 페이지의 제목과 본문 텍스트에서 검색한다.
- 사용자 동작: Ctrl+K 또는 사이드바 검색창에 입력 → 결과 목록에서 선택.
- 완료 기준
  - 결과마다 페이지 제목, 트리 경로, 일치 부분이 강조된 본문 일부를 보여 준다.
  - 결과를 고르면 그 페이지가 열리고 첫 일치 위치로 스크롤되며, 그 일치를 1.5초 옅게 강조한다(F-11의 찾기 코드를 쓰고 찾기 막대는 열지 않는다, D-59). 본문에 일치가 없고 제목에만 일치하면 페이지 맨 위를 연다. 서식 경계를 걸친 일치도 평문 기준으로 찾아 그 위치로 간다. 1~2글자 검색 결과도 편집기에서 같은 검색어를 다시 찾아 첫 위치로 간다. 위치를 못 찾으면 맨 위를 연다(D-28).
  - 한글 단어의 일부(예: "회의록"에서 "회의")로도 찾아진다.
  - 검색을 열거나 검색어를 보낼 때 저장 대기 중인 내용을 먼저 저장한다. 그래서 방금 입력한 내용도 검색에 나온다(D-28).
  - 휴지통의 페이지는 결과에 나오지 않는다.
  - 성능은 NF-04를 따른다.
- 범위: PDF·이미지 내부 텍스트 검색은 후순위(F-27).
- 오프라인 동작: 전부 동작한다(로컬 색인).
- 구현 메모(D-06): SQLite FTS5 전문 검색 색인. 저장 때 TipTap JSON에서 평문을 뽑아(Rust에서, D-17) 제목·본문을 색인에 함께 갱신한다(같은 트랜잭션).
  - rusqlite 0.41 `bundled`(SQLite 3.54.1)에서 FTS5 trigram 동작 확인(NOTE-backend1, 2026-10-26, D-15).
  - 한글 부분 일치: 기본 `unicode61` 토크나이저는 띄어쓰기 단위 어절을 한 토큰으로 보아 조사가 붙은 말("회의록에서")의 중간을 찾지 못한다. 그래서 `trigram` 토크나이저(부분 문자열 일치)를 쓴다.
  - 주의: trigram은 3글자 미만 검색어가 전문 검색(MATCH)에서 아무것도 찾지 못한다(SQLite 공식 문서). "회의"처럼 1~2글자 검색어는 같은 trigram 테이블에 `LIKE '%검색어%'`로 조회한다. 이때는 색인을 못 쓰고 테이블 전체를 훑으므로 NF-04 기준(0.5초)을 구현 때 측정한다.
  - 대소문자 구분 없음(trigram 기본값 `case_sensitive 0`). trigram 테이블에서 LIKE 색인을 쓰려면 `remove_diacritics`를 켜지 않는다(SQLite 공식 문서).
  - 출처: https://www.sqlite.org/fts5.html (trigram tokenizer 절)

## F-05 자동 저장 — MVP

- 설명: 저장 버튼 없이 편집 내용을 로컬에 저장한다.
- 사용자 동작: 없음(편집만 하면 된다). 저장 상태 표시("저장됨"/"저장 중")를 본다.
- 완료 기준
  - 마지막 입력 후 1초 안에 저장된다(NF-02).
  - 페이지 전환, 창 닫기, 앱 종료 때 저장되지 않은 내용을 먼저 저장한다.
  - 창을 닫을 때 저장이 실패하거나 3초 안에 끝나지 않으면 닫지 않고 "저장하지 못한 내용이 있습니다 [다시 저장] [그래도 닫기]"를 묻는다(D-19).
  - 입력을 멈추고 "저장됨"이 보인 뒤에는 앱을 강제 종료(작업 관리자)해도 다시 열면 내용이 남아 있다. 계속 입력하는 중에 강제 종료하면 마지막 저장 뒤(최대 5초, NF-02) 입력은 잃을 수 있다(D-28).
  - 저장에 실패하면(디스크 가득 참 등) 화면에 알리고, 편집 중인 내용은 메모리에 남겨 5초마다 저절로 다시 시도한다(입력이 없어도). 알림의 "지금 다시 저장"으로 바로 다시 시도할 수 있다. 휴지통으로 간 페이지는 다시 보내지 않는다.
  - 다른 프로그램(백업·동기화 등)이 데이터 파일을 잡고 있어 5초 안에 쓰지 못하면 디스크 문제와 구분해 "다른 프로그램이 데이터 파일을 쓰는 중이라 저장하지 못했습니다"를 알린다. 다시 시도는 위와 같다. 5초는 저장 명령을 보낸 때부터 잰다. 저장이 막혀 있어도 다른 페이지 열기는 기다리지 않는다(D-41).
  - 저장 실패·다시 시도 중인 페이지를 떠났다 돌아오면 DB 본문이 아니라 저장 대기분(보내는 중인 본문 포함)으로 연다. 저장 상태는 실패·다시 시도 중으로 보이고 "저장됨"으로 보이지 않는다(D-37).
- 오프라인 동작: 전부 동작한다.
- 저장 단위(D-06): 페이지 1개의 TipTap JSON 본문을 SQLite 트랜잭션 하나로 저장하고 검색 색인(F-04)도 같은 트랜잭션에서 갱신한다.

## F-06 마크다운 내보내기 — MVP

- 설명: 페이지를 표준 마크다운 파일로 내보낸다. SQLite만 쓰는 저장 방식(D-06)에서 데이터 이식성을 맡는 기능이다.
- 사용자 동작: 페이지 메뉴의 "마크다운으로 내보내기" → 하위 페이지 포함 여부를 고른다 → 폴더 선택 창에서 저장할 폴더를 고른다.
- 완료 기준
  - F-02의 블록이 마크다운으로 바뀐다: 제목 `#`, 목록 `-`/`1.`, 체크리스트 `- [ ]`/`- [x]`, 코드 펜스(백틱 3개 + 언어 이름), 표는 GFM 표, 이미지 `![](상대 경로)`.
  - 고른 폴더 안에 새 폴더 하나를 만들고 그 안에만 쓴다. 기존 파일을 덮어쓰지 않는다(D-21).
  - 이미지 파일은 내보낸 폴더의 `images\` 한 곳으로 함께 복사되어, 내보낸 폴더만 다른 곳에 옮겨도 이미지가 보인다(D-21).
  - 하위 페이지 포함이면 트리 구조가 폴더 구조로 내보내진다. 파일 이름에 쓸 수 없는 문자와 같은 이름 충돌은 바꿔서 피한다.
  - 내보낸 파일을 VS Code 마크다운 미리보기로 열었을 때 블록 종류가 알아볼 수 있게 보인다.
  - 마크다운으로 표현되지 않는 정보가 있으면 내보내기 후 알린다(예: 표 셀 안의 여러 줄·목록).
  - 문단 정렬(F-02.8)은 내보내지 않고 글자만 나간다. 표준 마크다운에는 정렬 표기가 없고, HTML 태그를 섞어 남기지 않는다(평문 마크다운의 한계, D-44). 정렬이 빠진 것은 따로 알리지 않는다.
  - 코드 블록의 복사 버튼(F-02.4, D-55)은 본문 JSON에 없으므로 내보낸 파일에 나오지 않는다. 코드 펜스에는 코드 글과 언어 이름만 나간다.
  - 내보내기가 끝나면 [폴더 열기]로 마지막에 내보낸 폴더를 탐색기로 연다. 전용 명령 `open_export_dir`가 그 폴더만 열고, 화면은 경로를 넘기지 않는다. opener 권한 범위(D-18)는 넓히지 않는다(D-30).
- 오프라인 동작: 전부 동작한다.
- 구현 메모(D-25): DB의 TipTap JSON을 직접 만든 변환기로 마크다운으로 바꾼다(`@tiptap/markdown`·`marked`는 쓰지 않음). `@tiptap/markdown`은 공식 문서 기준 "early release"이고 표는 셀마다 자식 노드 1개만 지원한다(https://tiptap.dev/docs/editor/markdown). 파일 쓰기와 폴더 선택 창은 Rust가 한다(`tauri-plugin-dialog`, D-21).

## F-07 앱 시작 시 마지막 페이지 열기 — MVP(사용자 확정, 2026-10-26)

- 설명: 앱을 다시 켜면 마지막으로 보던 페이지가 열린다.
- 완료 기준
  - 앱을 닫았다 다시 열면 마지막 페이지가 열리고 트리 펼침 상태도 그대로다.
  - 마지막 페이지가 휴지통에 있거나 삭제되었으면 트리의 첫 페이지를 연다. 페이지가 하나도 없으면 "새 페이지" 안내를 보여 준다.
  - 창 크기·위치를 기억한다(공식 `tauri-plugin-window-state`, D-17). 창 최소 크기는 900×600px다(D-22). 처음 실행할 때(기억한 크기가 없을 때) 창 크기는 1200×800px다(D-30).
  - 화면 상태를 기억한다: 테마·강조색(F-09), 사이드바 너비·접힘, AI 패널 열림, 최근 연 페이지 5개. 데이터 폴더의 DB(`app_state`)에 저장한다(D-19, NF-01 백업에 포함). DB 명령이 병합되기 전까지만 임시로 `localStorage`에 둔다(D-30).
- 오프라인 동작: 전부 동작한다.

## F-08 AI 사이드 패널 — MVP

- 설명: 편집 영역 오른쪽에 접었다 펼 수 있는 AI 패널을 둔다. Claude API를 쓴다(D-05). AI는 부가 기능이다.
- 사용자 동작: 텍스트를 선택하거나 현재 노트를 대상으로 패널에서 작업을 고른다 → 결과를 패널에서 보고 "삽입"·"바꾸기"·"복사" 중 하나를 누른다. "바꾸기"는 다듬기(F-08.2)에만 있다(D-30).
- 완료 기준(공통 원칙, 아이디어 노트 5절)
  - **AI 없이 완결**: API 키를 등록하지 않았거나 패널을 접은 상태에서도 F-01~F-07의 모든 완료 기준이 충족된다.
  - **오프라인 비활성**: PC가 네트워크에 연결되지 않았으면(Windows 연결 상태 기준, `navigator.onLine`) AI 작업 버튼이 비활성화되고 "오프라인" 표시가 보인다. 연결이 돌아오면 `online` 이벤트로 앱을 다시 켜지 않아도 바로 활성화된다. 네트워크에는 붙었지만 인터넷이 안 되는 경우는 호출 실패로 다룬다(패널에 이유를 보이고 횟수에 세지 않음, D-28).
  - **실패 격리**: API 호출이 실패하거나(네트워크 끊김, 시간 초과, 크레딧 소진, 키 오류) 응답을 기다리는 동안에도 편집기 입력·자동 저장이 막히지 않는다. 실패하면 패널에 이유를 보여 주고 노트 본문은 바뀌지 않는다.
  - **사용자 확인 후 반영**: AI 결과는 사용자가 "삽입"·"바꾸기"를 누르기 전에는 노트에 들어가지 않는다. 반영한 뒤 Ctrl+Z로 되돌릴 수 있다(F-03).
  - 크레딧 소진(API가 크레딧 부족 오류를 돌려줌)이면 "이번 달 크레딧 소진" 안내를 보여 준다.
  - **끝난 이유**: 응답이 출력 상한(F-08.5)·거부·문맥 초과로 끝나면 정상 완료로 보지 않고 결과에 그 이유를 표시한다(D-31). 이때 요약·다듬기·질의응답 모두 "삽입"·"바꾸기"를 끄고 "복사"만 둔다(D-34).
  - **삽입 위치**: "삽입"은 결과를 늘 새 블록으로 넣는다. 선택 끝(선택이 없으면 커서)이 든 최상위 블록 바로 아래에 넣고 그 블록을 쪼개지 않는다. 커서가 한 번도 놓인 적이 없으면 요청 범위 아래에 넣는다(D-35).
  - **화면을 바꿀 때**: 다른 페이지·설정·휴지통으로 가면 진행 중인 AI 요청을 멈춘다. 설정·휴지통에 갔다 같은 페이지로 돌아오면 이미 받은 결과가 그대로 보인다. 다듬기 결과는 돌아온 뒤에는 "바꾸기"를 끄고 "삽입"·"복사"만 둔다(D-35, D-36).
  - **패널을 닫을 때**: AI 패널을 닫았다 다시 열어도 받은 요약·다듬기 결과가 그대로 있다. 다듬기 "바꾸기"를 Ctrl+Z로 되돌리면 그 결과의 "삽입"이 다시 켜진다(D-43).
  - **답 형식**: AI 답은 마크다운 기호 없이 평문으로 받는다(프롬프트에서 요구, D-42).
  - **기본 오류 문구**: 오류 종류에 맞는 안내가 없으면 "AI 요청이 실패했습니다"를 보인다(D-36, 계약-AI 4.1).
- 구현 메모(D-21): AI 호출은 Rust가 한다. 키는 화면(WebView)으로 넘어오지 않고 CSP `connect-src`에 API 주소를 열지 않는다. 결과는 Tauri `Channel`로 흘려 보낸다. 동시에 진행하는 AI 요청은 1개다(진행 중이면 새 요청을 거부하고 알림).
- 모델: 가벼운 작업은 `claude-haiku-5-5`, 긴 노트 분석·글쓰기는 `claude-sonnet-5-5`(D-05). 작업별 배정은 아래 표.
- 오프라인 동작: 비활성화(위 기준).

### F-08.3 현재 노트 질의응답 — MVP(D-09)
- 설명: 열린 페이지 내용을 근거로 질문에 답한다.
- 대화 UI
  - 패널 아래 입력창에 질문을 쓰고 Enter로 보낸다(Shift+Enter는 줄바꿈). 질문과 답이 위에서 아래로 쌓인다.
  - 답에는 "삽입"(새 블록으로 넣기, 위치는 F-08 "삽입 위치", D-35)·"복사" 버튼이 있다.
  - 대화는 페이지마다 따로다. 다른 페이지로 가면 그 페이지의 대화가 보인다. 대화는 앱을 끄면 지워지고 DB에 저장하지 않는다(노트 내용이 대화 기록으로 남지 않게 함).
  - "새 대화" 버튼으로 지금 페이지의 대화를 지운다.
  - 답을 받는 중에는 "중지" 버튼이 있고, 그동안에도 편집은 된다(F-08 실패 격리).
- 보내는 내용: 질문마다 현재 페이지 본문(평문, 보낼 때 시점) + 이 페이지의 이전 대화 + 새 질문. 질문 1개는 호출 1회로 센다(F-08.5).
- 입력 상한(2만 자, F-08.5)을 넘을 때
  - 페이지 본문만으로 2만 자를 넘으면: 질문을 보내지 않는다. "이 노트는 2만 자를 넘어 전체를 보낼 수 없음. 질문할 부분을 선택하세요"를 보여 준다. 사용자가 본문에서 범위를 선택하면 그 선택 영역을 대상으로 질의응답한다(패널에 "대상: 선택 영역 n자" 표시). 자동으로 잘라 보내지 않는다.
  - 본문은 2만 자 이하지만 이전 대화를 더하면 넘으면: 오래된 대화부터 빼서 맞추고, 패널에 "앞 대화 n개는 이번 질문에 포함되지 않음"을 보여 준다.
- 완료 기준
  - 1만 자 노트에서 질문을 3번 연달아 하면, 세 번째 답이 앞 질문·답을 이어받는다(예: "그중 두 번째는?"에 맞게 답함).
  - 2만 자를 넘는 노트에서는 질문 버튼이 막히고 위 안내가 나오며, 범위를 선택한 뒤에는 질문이 된다.
  - AI 전송 제외(F-08.5) 페이지에서는 입력창이 비활성화된다.

### F-08.5 AI 사용 제어 — MVP
- 설명: 크레딧 급소진과 민감 정보 전송을 막는다(아이디어 노트 5절).
- 완료 기준
  - **호출 횟수 상한**: 하루 호출 횟수 상한(기본 50회)을 넘으면 AI 버튼이 비활성화되고 "오늘 상한 도달"과 남은 시간이 보인다. 상한은 설정에서 바꿀 수 있다. 횟수는 앱을 다시 시작해도 유지된다. "하루"는 PC 지역 날짜이고 남은 시간은 자정까지다. API가 응답을 보내기 시작하면 1회로 센다(그 뒤 중지·중간 오류도 셈). 연결 실패·오류 응답과 키 "확인" 시험 호출은 세지 않는다(D-21, 계약-AI 6절).
  - **입력 길이 상한**: 한 번에 보내는 입력(본문·선택 + 이전 대화 + 질문, 프롬프트 상수 제외)이 상한 2만 자(유니코드 문자 수, 바꿀 수 없음)를 넘으면 보내지 않고, 길이 초과를 알리며 선택 범위를 줄이라고 안내한다. 자동으로 잘라 보내지 않는다(질의응답의 이전 대화 처리는 F-08.3).
  - **출력 상한**: 요청마다 최대 출력 토큰을 정해 보낸다: 요약 1,024, 다듬기 16,000, 질의응답 4,096 토큰(D-21). 상한에 걸려 잘린 결과에는 "잘림"을 표시하고 정상 완료로 보지 않아 "삽입"·"바꾸기"를 끄고 "복사"만 둔다(세 작업 모두, D-34).
  - **AI 전송 제외 노트**: 페이지마다 "AI 전송 제외"를 켤 수 있다. 켠 페이지에서는 AI 버튼이 비활성화되고 그 페이지의 어떤 내용도 API로 나가지 않는다. 하위 페이지에도 적용할지 고를 수 있다. 하위 포함으로 켜면 그 아래에 새로 만들거나 옮겨 온 페이지도 제외되고, 밖으로 옮겨 나간 페이지는 자기 설정이 없으면 풀린다. 휴지통 이동·복원은 설정을 바꾸지 않는다. 설정은 다시 시작해도 유지된다(D-19 `pages.ai_exclude`). 알려진 한계: 제외 판정은 화면이 보낸 `pageId`·본문을 기준으로 하므로 화면 코드가 오염되면 우회될 수 있다(D-33).
  - 사용 기록(날짜별 호출 수·입력 길이)을 설정 화면에서 볼 수 있다. 노트 내용은 기록에 남기지 않는다.
- 오프라인 동작: 설정 변경은 오프라인에서도 된다.

### F-08.6 API 키 등록 — MVP(사용자 확정, 2026-10-26)
- 설명: AI를 쓰려면 Claude API 키가 필요하다. 키는 OS 키체인에 둔다(NF-05).
- 사용자 동작: 설정 화면에서 키 붙여넣기 → "확인하고 저장" 버튼 하나로 시험 호출과 저장을 함께 한다(D-30). "삭제"로 지운다.
- 완료 기준: 저장한 키가 화면에 다시 전체로 보이지 않는다(끝 4자리만). 키를 지우면 AI 버튼이 비활성화되고 "API 키 없음" 안내가 보인다. NF-05의 기준을 충족한다.
- 키 저장: 시험 호출(크레딧을 쓰지 않음)을 통과해야만 저장한다. 키가 틀리면 저장하지 않고 이유를 보인다(D-21).
- 오프라인 동작: 키 삭제는 된다. 키 저장은 온라인에서만 된다(시험 호출 필요, D-21).

## F-09 테마 — 사용자 확정(2026-10-27, D-45)

- 설명: 화면 색을 라이트·다크·Windows 설정 따름 가운데 고르고, 강조색을 프리셋 5개 가운데 고른다. 색을 하나씩 직접 고르는 편집기는 없다(F-29 후순위).
- 사용자 동작: 설정(S-08) `일반` 구역 › 테마 세그먼트(`Windows 설정 따름` 기본·`라이트`·`다크`)와 강조색 프리셋 5개(기본 먹청록) 중 하나를 누른다.
- 완료 기준
  - 고르면 앱을 다시 켜지 않아도 모든 화면에 바로 적용된다. `Windows 설정 따름`이면 앱이 켜진 채 Windows 테마를 바꿔도 따라간다.
  - 고른 값은 다시 켜도 유지된다. 화면 상태 `ui_state`의 `theme`(`system`/`light`/`dark`)·`accent`(프리셋 이름)에 저장하므로 데이터 폴더 백업에 포함된다(F-07, D-19). 알 수 없는 값이면 기본값(`system`, 먹청록)으로 보인다.
  - 번쩍임 없음: 앱을 켤 때 `ui_state`를 읽기 전에 고른 것과 다른 테마·강조색(예: 다크를 골랐는데 흰 바탕)이 보이지 않는다. 창 배경도 테마에 맞는다.
  - 대비: 프리셋 5개 × 라이트·다크 10조합 모두 글자 대비 WCAG AA 4.5:1 이상(강조색 글자/편집 바탕, 강조 위 글자/강조색), 포커스 표시·끌기 위치선은 3:1 이상(WCAG 1.4.11). 대비표는 화면설계 토큰 절에 둔다.
  - 프리셋은 강조 관련 토큰만 바꾼다. 면·글자·상태(위험·경고·성공) 색은 바뀌지 않는다.
- 오프라인 동작: 전부 동작한다. 원격 테마·글꼴을 받지 않는다(NF-06).
- 구현 메모: 색은 모두 `src/styles/tokens.css` 토큰이고 테마는 `<html data-theme>`, 강조색은 `<html data-accent>`(`src/styles/accents.css`)로 바꾼다. 기본값(`system`·먹청록)은 속성을 두지 않고 `prefers-color-scheme`을 따른다. 새 라이브러리·명령 계약 변경 없음. 번쩍임 대책 방법(예: 창을 숨긴 채 띄우고 적용 뒤 보이기)은 구현이 정하되, `tauri.conf.json`(공용 파일)을 고치면 pm에 먼저 알린다.
- 구현 상태(2026-10-28 확인, main fadd424, P5-2 ee305fd·6762858)
  - 설정 `일반` 구역의 테마 세그먼트 3개·강조색 견본 5개(`src/app/SettingsView.tsx`, `src/app/appearance.ts`), 저장은 `ui_state.theme`·`accent`. 기준 값은 `ui_state`다.
  - 첫 페인트 전 적용: `src/app/appearance.ts`가 `ui_state`에서 읽었거나 저장에 성공한 값만 `localStorage` 사본(`wy-note-appearance`)으로 남기고, `public/theme-init.js`가 `<head>`에서 동기로 이 사본을 읽어 `data-theme`·`data-accent`를 넣는다(CSP `script-src 'self'`라 인라인 대신 파일). 사본은 `ui_state`의 사본일 뿐 저장의 기준이 아니다(D-19·D-30의 저장 위치 원칙은 그대로).
  - 남은 것: 창 바탕색(WebView가 그려지기 전 창 배경)은 아직 테마를 따르지 않는다(`tauri.conf.json`에 창 배경 설정 없음, 후속 후보). 위 "창 배경도 테마에 맞는다"는 이것이 끝나야 채워진다.

## F-10 목차 — 사용자 요청(2026-11-04, D-48, P5-6)

- 설명: 지금 페이지 본문의 제목 1·2·3(F-02.1)을 목록으로 보여 주고, 항목을 누르면 그 제목으로 바로 간다. 들여쓰기·글자 크기로 위계를 보여 문서 구조가 보이게 한다. 페이지 제목(F-01.2)은 목록에 넣지 않는다. 화면 모양은 화면설계 S-06 목차(v0.7)가 기준이다.
- 사용자 동작
  - 마우스: 편집 영역 오른쪽 가장자리(보이는 표시 없는 감지 띠 24px)에 마우스를 150ms 대면 목록이 본문 위에 떠서 나온다. 띠와 목록 둘 다에서 마우스가 떠나고 300ms 뒤 닫힌다(그 안에 다시 들어오면 닫지 않는다). 편집기의 `/` 메뉴·링크 메뉴가 뜨면 마우스로 연 목록은 바로 닫히고, 메뉴가 떠 있는 동안에는 띠에 마우스를 대도 열리지 않는다(D-50).
  - 키보드: 페이지 화면에서 `Ctrl+Shift+O`로 열고 다시 누르면 닫는다. 목록 안에서 ↑↓·Home·End로 옮기고 Enter·Space로 그 제목으로 간다. Esc는 닫고 편집기의 원래 자리로 돌아간다. Tab·바깥 클릭도 닫는다. 키보드로 연 목록은 마우스가 떠나도 닫히지 않는다.
- 완료 기준
  - 목록은 본문의 제목 1·2·3을 문서 순서대로 모두 보여 준다. 들여쓰기 제목1 0·제목2 12·제목3 24px, 글자는 제목1 14px 굵게(600)·제목2 13px·제목3 13px 옅은 글자(2단계). 긴 제목은 한 줄로 말줄임한다. 글자가 없는 제목은 `(제목 없음)`으로 보인다.
  - 본문에 제목이 하나도 없으면 띠에 마우스를 대도, `Ctrl+Shift+O`를 눌러도 목록이 뜨지 않는다.
  - 본문을 고치면(제목 추가·삭제·수준 변경·글자 수정) 다음에 열 때, 열려 있으면 바로 목록에 반영된다.
  - 지금 보이는 제목이 강조된다: 머리가 '읽는 선'(도구 막대 아래 32px) 위에 있는 제목 가운데 마지막 것. 첫 제목보다 위를 보고 있으면 강조가 없고, 맨 아래까지 스크롤했으면 화면에 보이는 제목 가운데 마지막 것.
  - 항목을 누르면(마우스·Enter·Space) 그 제목 위끝이 도구 막대 아래 24px에 오도록 바로(부드러운 스크롤 없이) 스크롤하고, 커서를 그 제목 맨 앞에 놓고, 목록을 닫는다. 본문 내용은 바뀌지 않는다(자동 저장·실행 취소 기록이 생기지 않는다).
  - 키보드로 열면 지금 제목(없으면 첫 항목)에 포커스가 간다.
  - 목록은 편집 영역의 보이는 오른쪽 끝에 붙는다. AI 패널이 그리드 열로 열려 있으면 편집 영역 오른쪽, 좁은 창에서 겹쳐 떠 있으면(D-39) 그 패널 왼쪽 경계가 오른쪽 끝이다. 감지 띠는 편집 영역 스크롤바와 겹치지 않아 스크롤바를 끌 수 있다. 제목이 많아 목록이 편집 높이를 넘으면 목록 안에서 스크롤한다.
- 오프라인 동작: 전부 동작한다.
- 구현 메모(D-48): 새 라이브러리 없이 TipTap 문서(`editor.state.doc`)의 `heading` 노드(`attrs.level` 1~3)만 읽어 만든다. 저장 형태·DB·Tauri 명령 계약은 바뀌지 않는다. 표 셀 등 다른 블록 안에 든 제목은 StarterKit 스키마상 생기지 않는다고 보고 최상위 제목만 대상으로 해도 된다(구현이 확인). `Ctrl+Shift+O`는 앱 코드(`src/`)에서 쓰지 않는 키임을 확인했다(2026-11-04). TipTap·WebView2 기본 키와 겹치는지는 구현이 확인하고, 겹치면 pm에 알린다.

## F-11 페이지 안 찾기·바꾸기 — 사용자 결정(2026-11-08, D-59, P7)

- 설명: 지금 열린 페이지 본문에서 낱말을 찾아 일치를 모두 강조하고, 하나씩 옮겨 다니며, 바꾸기·모두 바꾸기를 한다. 앱이 직접 그리는 막대이고 WebView2 기본 찾기 막대는 쓰지 않는다(D-56). 화면(자리·모양·문구·포커스 순서)은 화면설계 S-14(NOTE-design, 자리는 도구 막대 바로 아래 한 줄)가 기준이다.
- 열기
  - 페이지 화면(제목 칸·본문·AI 패널에 포커스가 있어도)에서 Ctrl+F는 찾기 막대를 연다. Ctrl+K는 노트 검색 창(F-04) 그대로다. 휴지통·설정·빈 상태 화면에서 Ctrl+F는 검색 창(S-05)을 연다(D-59). 대화상자·메뉴·검색 창이 떠 있으면 열지 않는다(WebView2 찾기 막대도 열리지 않는다).
  - 본문에 한 줄·200자 이하 선택이 있으면 그 글로 찾는 말을 채우고, 아니면 지난 찾는 말을 전체 선택한 채로 둔다.
  - 막대가 열린 채 Ctrl+F를 누르면 찾기 입력칸으로 가서 전체 선택한다.
- 찾는 범위
  - 본문만 찾는다: 문단·제목·목록·체크리스트·인용·표 칸·코드 블록. 페이지 제목은 넣지 않는다(D-59, 제목은 입력칸이라 일치 여러 개를 강조할 수 없다).
  - 한 블록(textblock) 안에서만 맞춘다. 굵게·링크 같은 서식 경계를 걸친 일치는 찾는다. 두 블록(표의 두 칸 포함)에 걸친 일치와, 줄바꿈·이미지 같은 글이 아닌 요소를 건너는 일치는 찾지 않는다.
  - 대소문자 구별 없음(F-04 검색과 같음), 유니코드 NFC로 맞춰 비교, 띄어쓰기는 그대로. 정규식·낱말 단위·대소문자 켜기 옵션은 없다. 1글자부터 찾는다.
- 표시
  - 모든 일치를 `--color-mark`로, 지금 일치는 한 단계 진하게(모양은 S-14) 칠한다. 막대에 `n/m`, 일치가 없으면 `0/0`과 "일치 없음"을 보인다. 1,000개를 넘으면 `n/1,000+`로 보이고 강조도 앞 1,000개까지만 그린다.
  - 처음 열거나 찾는 말을 바꾸면 커서 위치 다음의 첫 일치가 지금 일치다. 지금 일치는 도구 막대·찾기 막대에 가리지 않는 자리로 바로(부드러운 스크롤 없이, F-10과 같음) 스크롤한다.
- 이동: 찾기 입력칸에서 Enter는 다음, Shift+Enter는 이전(한글 조합 중 Enter는 입력기 몫). 페이지 화면 어디서나 F3·Ctrl+G는 다음, Shift+F3·Ctrl+Shift+G는 이전이다. 막대가 닫혀 있으면 이 키들은 지난 찾는 말로 막대를 열고 그 방향으로 옮긴다(지난 말이 없으면 빈 막대만 연다). 끝에서 처음으로, 처음에서 끝으로 돌아간다.
- 닫기: 막대 안에서 Esc, 또는 닫기 버튼. 강조를 모두 지우고 편집기로 포커스를 돌린다. 지금 일치가 있으면 그 글을 선택한 채로, 없으면 열기 전 커서 자리로 돌아간다. 페이지를 바꾸면 막대는 열린 채 새 페이지에서 같은 말로 다시 찾는다.
- 바꾸기(D-59)
  - 여는 방법: 찾기 막대 안의 펼치기 버튼(`aria-expanded`)으로 바꾸기 줄을 펴고 접는다. 페이지 화면에서 Ctrl+H는 막대를 바꾸기 줄이 펴진 채로 연다(막대가 열려 있으면 바꾸기 줄을 편다). 이때 찾는 말이 비어 있으면 찾기 입력칸, 있으면 바꾸기 입력칸에 포커스가 간다. 펼침 상태는 앱을 켜 둔 동안 기억한다. Ctrl+F로 열면 지난 펼침 상태 그대로 열고, Ctrl+F는 바꾸기 줄을 펴거나 접지 않는다.
  - Ctrl+H는 개발·릴리스 모두 앱이 받아 WebView2 기본 동작을 막는다. 페이지가 아닌 화면에서는 아무것도 하지 않는다. WebView2 공식 문서의 브라우저 단축키 목록에는 Ctrl+H가 없지만, 그 목록은 "including but not limited to"라 빠짐없는 목록이 아니다. 그래서 겹치는지와 상관없이 앱이 받는다. 구현은 실제 앱에서 Ctrl+H가 아무 창도 열지 않음을 확인한다.
  - 바꾸기 입력칸은 한 줄이고 빈 값도 된다. 빈 값으로 바꾸면 일치를 지운다. 찾는 말·바꿀 말은 앱을 켜 둔 동안 기억한다.
  - 버튼은 두 개다. '바꾸기'는 지금 일치 하나를 바꾸고, 바꾼 글 바로 뒤의 다음 일치를 지금 일치로 삼아 그 자리로 스크롤한다. 바꾼 글 안은 다시 찾지 않아서, 바꿀 말에 찾는 말이 들어 있어도 같은 자리를 되풀이하지 않는다. '모두 바꾸기'는 페이지 본문의 일치를 모두 바꾼다. 1,000개를 넘어 강조하지 않은 일치까지 포함하고, 누른 순간의 일치만 한 번 훑으며 바꾼다. 바꾸기 입력칸에서 Enter는 '바꾸기', Ctrl+Alt+Enter는 '모두 바꾸기'와 같다(VS Code와 같음, 한글 조합 중 Enter는 입력기 몫). 찾기 입력칸의 Enter·Shift+Enter는 그대로 다음·이전이다.
  - 버튼을 누르면 미뤄 둔 다시 찾기(100ms)를 기다리지 않고 그 자리에서 다시 센 뒤 바꾼다. 화면의 강조가 문서보다 늦어 엉뚱한 곳을 바꾸는 일이 없어야 한다.
  - 바뀐 글의 서식: 바뀐 글 전체가 일치 첫 글자의 서식(굵게·링크·인라인 코드 등)을 따른다. 코드 블록 안에서는 평문으로 바뀌고, 문법 강조는 바뀐 글로 다시 칠한다. 표 칸 안에서는 그 칸 안에서만 바뀌고 행·열은 그대로다.
  - 실행 취소 단위(F-03): '바꾸기' 한 번이 실행 취소 한 번이다. 바로 앞의 타이핑이나 이어 누른 다른 '바꾸기'와 한 묶음으로 합치지 않는다(ProseMirror history는 500ms 안의 붙은 편집을 한 묶음으로 합치므로 `closeHistory`로 끊는다). '모두 바꾸기'는 거래(transaction) 하나로 해서 Ctrl+Z 한 번에 모두 되돌린다. 막대의 버튼에 포커스가 있을 때 Ctrl+Z·Ctrl+Y·Ctrl+Shift+Z는 본문의 실행 취소·다시 실행으로 간다. 찾기·바꾸기 입력칸 안에서는 입력칸 글자를 되돌린다(입력칸 기본 동작).
  - 바꾸기는 진짜 본문 편집이다. 자동 저장(F-05)·검색 색인 갱신(F-04)이 평소 편집처럼 일어난다.
  - 버튼 상태: 찾는 말이 비었거나 일치가 0개이면 '바꾸기'·'모두 바꾸기'를 끈다. 버튼은 사라지지 않고 꺼진다(F-02 도구 막대 규칙과 같음). 한글 조합 중에도 버튼 상태는 그대로 둔다.
  - 알림: '모두 바꾸기' 뒤에는 공통 알림(토스트)으로 "`n`개를 바꿨습니다"와 [실행 취소]를 보인다. 화면 읽기 프로그램도 같은 문장을 읽는다(토스트의 공통 낭독 규칙). `n`은 천 단위 쉼표를 찍은 실제 개수이고, 1,000개를 넘어도 그대로 쓴다. [실행 취소]는 본문에서 Ctrl+Z 한 번과 같다. 토스트가 떠 있는 동안 본문이 다른 편집으로 바뀌면 [실행 취소]를 거둔다. 그래야 그 버튼이 모두 바꾸기가 아닌 다른 편집을 되돌리지 않는다. 막대의 `n/m`은 다시 센 값으로 바뀐다. '바꾸기' 한 번 뒤에는 토스트 없이 `n/m`만 새로 바뀐다. 바꾼 뒤 일치가 남지 않으면 `0/0`과 "일치 없음"이 된다.
- 한글 조합
  - 찾기 입력칸: 조합 중인 글자까지 넣어 찾는다([pm 결정], D-59). 입력이 멈추고 100ms 뒤 다시 찾는다.
  - 본문(막대가 열린 채 편집할 때): 편집기가 조합 중(`view.composing`)이면 일치를 다시 세지 않고, 조합이 끝난 뒤 다시 센다. 조합 중에 꾸밈을 바꾸면 입력기 글자가 깨질 수 있어서다.
  - 막대를 닫은 직후 본문에 한글을 치면 첫 글자부터 조합 중 글자가 보인다(D-56의 버그가 다시 나지 않는다).
- 문서가 바뀔 때: 거래마다 기존 강조를 문서 변경에 맞춰 옮기고(`DecorationSet.map`), 입력이 멈추고 100ms 뒤 바뀐 문서로 다시 센다. 강조는 꾸밈이라 문서를 바꾸지 않는다. 그래서 찾기·이동·강조만으로는 자동 저장·실행 취소 기록이 생기지 않고, 강조가 본문 JSON·내보내기·AI·검색 색인에 들어가지 않는다.
- 범위 밖: 여러 페이지에 걸친 찾기·바꾸기(검색 창 F-04 몫), 페이지 제목 찾기·바꾸기, 정규식·대소문자 맞추기 바꾸기.
- 완료 기준
  - 위 열기·이동·닫기·개수·바꾸기·모두 바꾸기 동작이 모두 된다. Ctrl+F·Ctrl+H·F3·Shift+F3·Ctrl+G·Ctrl+Shift+G 어느 것도, 어느 화면에서도 WebView2 기본 창(찾기 막대 등)을 열지 않는다. 페이지가 아닌 화면에서 F3·Ctrl+G 계열과 Ctrl+H는 아무것도 하지 않는다.
  - 막대를 닫고 본문에 한글을 바로 치면 조합 중 글자가 보인다(Alt+Tab 없이).
  - 찾기·이동·강조는 실행 취소 기록·자동 저장을 만들지 않는다. 그래서 막대를 열고 닫은 뒤 Ctrl+Z 한 번은 찾기 전의 편집을 되돌린다.
  - '바꾸기'를 세 번 빠르게(500ms 안에) 눌러도 Ctrl+Z 세 번에 하나씩 되돌아간다. '모두 바꾸기'는 Ctrl+Z 한 번에 모두 되돌아가고, Ctrl+Y 한 번에 다시 모두 바뀐다. 버튼에 포커스가 있을 때도 그렇다.
  - 코드 블록·표 칸·굵게/링크 경계에 걸친 일치가 바뀐다. 바꾼 뒤 저장했다가 다시 열어도 블록 종류·표 모양이 그대로다.
  - 일치가 0개이면 두 버튼이 꺼져 있다. '모두 바꾸기' 뒤 화면 읽기 프로그램(Windows 내레이터)이 "`n`개를 바꿨습니다"를 읽는다. 토스트의 [실행 취소]는 모두 바꾸기를 한 번에 되돌린다. 그 사이 본문을 고쳤으면 [실행 취소]가 없다.
  - 성능(NF-04, 5회 측정의 최댓값)
    - 5만 자 페이지에서 다시 찾기 한 번 50ms 이하.
    - 막대를 연 채 본문을 타이핑할 때 지연이 막대를 닫았을 때와 같은 기준(p95 50ms·최대 100ms)을 지킨다.
    - 5만 자 페이지에서 일치 1,000개 이상(시험값 5,000개, 1글자 찾는 말)을 '모두 바꾸기'할 때, 누른 때부터 본문·개수가 화면에 반영될 때까지 300ms 이하. 그 뒤 첫 키 입력이 위 타이핑 기준을 지킨다. 자동 저장은 한 번만 일어난다(NF-02 디바운스).
    - 같은 페이지에서 '바꾸기' 한 번은 50ms 이하.
    - 코드 블록 30개 시험 페이지: 코드 블록 안 입력은 이미 기준을 넘는 문제(lowlight 전체 재강조, 다음 판 후보)라, 막대를 열어 더 느려지지 않는지만 본다. '모두 바꾸기'는 걸린 시간을 재어 적기만 한다.
    - 300ms·50ms는 기획 제안값이다(NF-04에 바꾸기 기준이 없어 새로 정함). 구현 중 무리인 값이 나오면 pm이 다시 올린다.
  - 새 라이브러리 없이 `@tiptap/pm` 꾸밈·거래로 만든다(라이브러리를 더하려면 사용자 결정).
- 오프라인 동작: 전부 동작한다.
- 구현 메모: 꾸밈은 이미 쓰고 있다(`src/editor/placeholder.ts`, `@tiptap/pm/view`). `closeHistory`는 `@tiptap/pm/history`(prosemirror-history)에 있다. 저장 형태·DB·Tauri 명령 계약은 바뀌지 않는다.

## 비기능 요구

### NF-01 로컬 데이터 위치
- 모든 노트·이미지·설정은 이 PC의 한 데이터 폴더 아래에 저장한다(D-04). 데이터 폴더는 Tauri 앱 데이터 폴더(`appDataDir`)다. Windows에서는 `%APPDATA%`(RoamingAppData) 아래 `tauri.conf.json`의 앱 식별자(identifier) 이름 폴더가 된다(Tauri 공식 문서: `appDataDir` = `${dataDir}/${bundleIdentifier}`, Windows `dataDir` = `{FOLDERID_RoamingAppData}`). 앱 식별자는 `com.wynote.desktop`이므로(D-14) 데이터 폴더는 `%APPDATA%\com.wynote.desktop`이다. 식별자를 바꾸면 데이터 폴더가 바뀌므로 바꾸지 않는다.
  - 그 아래 구성: SQLite 파일 `wy-note.db` 1개(D-06, D-17. 화면 상태 F-07도 여기, D-19) + 첨부 이미지 폴더(F-02.6).
  - 테스트용 예외: 디버그 빌드에서만 환경 변수로 데이터 폴더를 바꿀 수 있다. 릴리스 빌드는 이 환경 변수를 무시한다(D-22).
  - 출처: https://v2.tauri.app/reference/javascript/api/namespacepath/
- 완료 기준: 설정 화면에 데이터 폴더 경로가 보이고 "폴더 열기"로 탐색기에서 열린다(opener 권한은 데이터 폴더 범위로만, D-18). 앱을 끈 상태에서 데이터 폴더를 통째로 복사하면 백업이 된다.
- AI 호출(F-08) 말고는 노트 내용이 PC 밖으로 나가지 않는다.

### NF-02 자동 저장 간격
- 마지막 입력 후 1초 디바운스로 저장하고, 계속 입력 중이어도 5초마다 한 번은 저장한다.
- 저장은 SQLite 트랜잭션으로 원자적으로 해서(D-06), 저장 중 강제 종료되어도 이전 저장본이 깨지지 않는다.
- 저널 모드 WAL, `synchronous=NORMAL`(D-17). 앱 강제 종료로는 커밋한 내용이 사라지지 않는다. 전원 차단·OS 멈춤 때는 마지막 커밋 몇 개가 사라질 수 있으나 DB는 깨지지 않는다(https://www.sqlite.org/pragma.html#pragma_synchronous).
- 완료 기준: F-05의 완료 기준과 같다.

### NF-03 충돌 방지
- 앱은 한 번에 하나만 실행된다. 두 번째로 실행하면 새 창 대신 이미 켜진 창이 앞으로 온다(공식 `tauri-plugin-single-instance`, D-17).
- 사용자 1명·기기 1대(D-03, D-04)라 기기 간 동기화 충돌은 다루지 않는다.

### NF-04 성능 목표
- 앱 아이콘 클릭부터 편집 가능까지 3초 이내.
- 페이지 전환 1초 이내(F-01).
- 페이지 1,000개·전체 본문 약 1,000만 자에서 검색 결과 0.5초 이내(F-04). 1~2글자 검색어(LIKE 전체 훑기)도 이 기준으로 측정한다.
- 입력 지연: 페이지 본문 5만 자에서도 타이핑이 끊기지 않는다. 키 입력부터 화면 반영까지 p95 50ms 이하, 최대 100ms 이하. 한글 입력기 조합 중 끊김은 눈으로 판정한다(D-28).
- 메모리: 유휴 상태 앱 전체(WebView2 프로세스 포함) 300MB 이하. 이 PC는 RAM 16GB에서 개발 세션 여러 개가 함께 돌므로 낮게 잡았다(D-07).
  - 측정 방법(D-13, D-28): 1,000페이지 시험 데이터(D2) DB, AI 패널 닫힘, 앱을 켜고 페이지 하나를 연 채 입력 없이 둔 상태에서, 앱 프로세스(wy-note)와 그 앱이 띄운 msedgewebview2 프로세스 전체의 Private 메모리를 더한다. Working Set 합계(작업 관리자에 가까운 숫자)는 공유 DLL 페이지를 중복으로 세므로 판정에 쓰지 않고 참고로만 함께 적는다.
  - 기준선(D-12, 템플릿 빈 화면, 2026-10-26): 프로세스 7개(wy-note 1 + msedgewebview2 6), Private 합계 149.5~151.6MB, Working Set 합계 304.5~313.9MB.
  - 릴리스 빌드 측정은 실제 데이터 폴더를 쓰므로 사용자가 실사용을 시작하기 전에 끝낸다. 실사용 뒤 다시 재야 하면 사용자에게 먼저 묻는다(D-30).
  - TipTap·SQLite가 들어간 MVP에서 다시 잰다. 페이지 20개를 오가며 편집한 뒤의 메모리도 함께 잰다. 실행 취소 기록(F-03)은 지금 상한을 두지 않고, 이 측정에서 300MB를 넘으면 그때 상한을 정한다(D-28).
- 측정·판정 방법(D-28)
  - 시작 3초: 바로 가기 실행부터 마지막 페이지 편집기에 커서가 생겨 입력되는 때까지. 따뜻한 시작(앱을 한 번 켰다 끈 뒤)으로 판정하고 차가운 시작(재부팅 직후)은 참고로만 적는다.
  - 페이지 전환 1초: 트리 클릭부터 본문 첫 화면이 그려지고 입력되는 때까지.
  - 검색 0.5초: 마지막 키 입력부터 결과 목록이 보일 때까지(화면 입력 대기 120ms 포함, 사용자가 느끼는 시간).
  - 판정값: 5회 측정의 최댓값.

### NF-05 API 키 보관
- API 키는 Windows 자격 증명 관리자(OS 키체인)에 저장한다(아이디어 노트 6절).
- 키를 읽고 쓰는 코드는 한 모듈에 모은다. 다른 코드는 이 모듈을 거쳐서만 키에 접근한다(D-10: 배포하게 되면 이 모듈만 다시 설계).
- 완료 기준
  - 키가 소스 코드·저장소·설정 파일·데이터 폴더·로그 어디에도 평문으로 없다(데이터 폴더와 로그를 키 문자열로 검색해 0건).
  - 키 전체는 AI 호출과 키 "확인" 시험 호출 때만 읽는다. 화면에 보일 끝 4자리는 데이터 폴더(`app_state`)에 따로 둔다(D-21). 키 전체가 화면·로그·오류 메시지에 찍히지 않는다.
  - 키 접근 코드가 한 모듈에만 있다(코드 검색으로 확인).

### NF-06 오프라인 완결
- 네트워크를 끊은 상태(비행기 모드)에서 F-01~F-07이 모두 동작한다.
- 앱 코드(화면·Rust)는 AI 호출(F-08)과 키 "확인" 시험 호출(F-08.6) 말고는 네트워크 요청을 하지 않는다(업데이트 확인·원격 글꼴·원격 이미지·분석 도구 없음). 화면에 쓰는 아이콘·문법 강조 언어 정의는 앱에 포함하고 글꼴은 시스템 글꼴을 쓴다(D-22).
- 범위 밖(D-20): WebView2·Windows가 스스로 하는 통신(SmartScreen, 구성 요소 갱신 등)은 앱 코드의 요청이 아니므로 이 기준에 들지 않는다. 그 통신에 노트 내용이 실리지 않음은 테스트(T-NF06-03)로 확인한다.
- 완료 기준: 네트워크를 끊고 앱을 새로 시작해 페이지 생성·편집·이미지 붙여넣기·검색·내보내기가 모두 된다.
